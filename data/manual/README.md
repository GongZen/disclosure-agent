# 수작업 입력

PDF 로 온 문서 3건은 파서로 값을 뽑지 못한다. 1,054건 중 3건이라
PDF 표 파서를 따로 만드는 것보다 사람이 원문을 읽어 적는 편이 빠르고 정확하다.

## 대상

| 기업 | 접수일 | 보고서 | 회계연도 |
|---|---|---|---|
| KB금융 | 2026-06-19 | [기재정정]사업보고서 | 2025.12 |
| 한화에어로스페이스 | 2026-05-13 | 분기보고서 | 2026.03 |
| 한화오션 | 2024-05-14 | [기재정정]분기보고서 | 2024.03 |

KB금융은 앞선 XML 정정본(2026-03-24)이 담겨 있으나 그것은 중간 정정본이다.
6월 정정에서 재무상태표 값이 바뀌었으므로 이 PDF 가 최종본이다.

## 채우는 법

`pdf_facts.csv` 의 `값` 과 `단위` 칸을 채운다. 골든 데이터셋에 이미 있는
12행은 미리 채워져 있다.

```
값      원문에 적힌 그대로. 쉼표는 있어도 없어도 된다
단위    원 · 천원 · 백만원.  표 제목의 "(단위 : 백만원)" 을 보고 적는다
비고    원문에 없는 항목이면 "없음" 이라고 적는다. 비워두면 미입력으로 본다
```

## 어느 표에서 읽는가 — 헷갈리는 것들

### 유형자산 취득 (capex)

현금흐름표 본문에서 읽는다. 주석이 아니다.

```
연결 현금흐름표
   투자활동현금흐름
      유형자산의 취득        ← 이 값
```

주석의 유형자산 항목과 다르다. 셋이 서로 다른 값이다.

```
주석 · 유형자산의 구성 내역 · 취득원가
   그 시점에 보유한 자산의 원래 산 가격 총액
   10년 전에 산 건물도 포함된다. 잔액 개념

주석 · "취득" 행
   그 기간에 늘어난 유형자산 장부금액
   현금을 안 쓴 취득도 들어간다. 리스 · 합병으로 넘어온 것 · 건설중인자산 대체

현금흐름표 · 유형자산의 취득          ← 담는 것
   그 기간에 실제로 현금이 나간 금액
```

`fsvalue.py` 가 쓰는 태그가
`ifrs-full_PurchaseOfPropertyPlantAndEquipmentClassifiedAsInvestingActivities`
인데 뒤의 `ClassifiedAsInvestingActivities` 가 투자활동 현금흐름을 뜻한다.

### 부호

현금흐름표는 나간 돈을 `(1,234,567)` 로 적는다.

| 항목 | 어떻게 적나 |
|---|---|
| capex | 양수로. 괄호를 빼고 적는다 |
| cf_operating · cf_investing · cf_financing | 원문 부호 그대로. 음수면 `-` 를 붙인다 |

capex 만 양수로 통일하는 이유가 있다. "설비투자 규모가 더 큰 기업" 을
물었을 때 크기 비교가 바로 되어야 한다. XBRL 은 취득액을 양수로 태깅하고
현금흐름표는 유출이라 음수로 적어 두 경로가 반대였다. 전수 532쌍 중 199쌍이
부호만 달랐고 절댓값은 같았다. DECISIONS 2026-08-19 참조.

나머지 셋은 부호 자체가 정보다. 영업활동이 음수면 영업으로 현금을 벌지
못했다는 뜻이다.

## 기간 유형

```
instant      재무상태표. 어느 시점의 잔액
annual       사업보고서의 손익·현금흐름. 그 해 열두 달
cumulative   분기·반기 보고서의 누적. 그 해 첫날부터 그 시점까지
```

분기보고서 두 건은 `cumulative` 로 두었다. 1분기는 3개월치와 누적이 같아
구분이 필요 없다.
