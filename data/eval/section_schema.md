# section_schema.csv 안내

70개사 사업보고서의 절을 하나의 스키마로 모은 표다. 절마다 그 절에서 빈번한
낱말을 함께 담았다.

만들어진 경위와 왜 이런 구조인지는 `docs/TOC_SCHEMA.md` 에 있다. 이 문서는
파일을 어떻게 읽고 무엇을 채우는지만 적는다.

662행 · 20칸. 2025년 사업보고서 기준. 정정본은 최신 한 건만 썼다.

---

## 먼저 — 스프레드시트로 열어라

메모장이나 IDE 의 텍스트 뷰로 열면 칸이 어긋나 보인다. 파일이 깨진 것이 아니다.

값 안에 쉼표가 든 칸이 651개 있다. CSV 규격대로 따옴표로 감싸여 있어 파서는
정상으로 읽지만, 원시 텍스트로 보면 쉼표 자리에서 칸이 밀린 것처럼 보인다.

```
9,10. 투자자산 및 파생상품                     ← 제목에 쉼표가 들어 있다
18. 종속기업투자, 관계기업투자 및 공동기업투자
```

662행 전부 20칸으로 확인했다. 구조는 정상이다.

## 칸 설명

### 작업용 — 여기를 채운다

| 칸 | 무엇을 적나 |
|---|---|
| `뺄것` | 지금 낱말 중 빼야 할 것. 낱말을 공백으로 구분해 적는다 |
| `더할것` | 이 절을 묻는 질의에 나올 법한데 없는 낱말 |
| `메모` | 판단 근거를 남기고 싶으면 |

### 대상 표시

| 칸 | 무엇인가 |
|---|---|
| `작업대상` | `O` 면 지금 채울 것. 5곳 이상이 쓰는 절이다 |

662행 중 165행이 `O` 다. 나머지 497행은 5곳 미만이라 지금은 안 채운다.
표에 남긴 이유는 빼 버리면 "왜 없지" 를 나중에 다시 묻게 되기 때문이다.

`O` 가 붙은 165행이 사업보고서 본문의 85.8% 를 덮는다.

### 절을 가리키는 칸

| 칸 | 무엇인가 |
|---|---|
| `대분류` | 로마숫자 I~XII. 70개사가 완전히 같다 |
| `열쇠` | 이 절을 식별하는 값. 코드가 대조할 열쇠다 |
| `열쇠뜻` | 사람이 읽을 이름. 가장 많이 쓰인 제목에서 앞 번호를 뗀 것 |
| `다른제목` | 같은 열쇠에 붙은 2~4번째로 흔한 이름 |
| `이름가짓수` | 이 열쇠에 몇 가지 이름이 묶였나 |
| `열쇠종류` | `tag` 또는 `title` |

`열쇠` 와 `열쇠뜻` 을 한 칸에 합치지 않았다. 나중에 검색 코드가
`section.aclass` 와 대조할 때 `열쇠` 를 그대로 써야 하기 때문이다.
스프레드시트에서는 나란히 보인다.

앞 번호를 뗀 이유는 기업마다 다르기 때문이다. 어떤 회사는 13번이 무형자산이고
어떤 회사는 15번이다. 번호를 남기면 열쇠의 뜻이 아니라 한 회사의 사정이
표에 박힌다.

#### 열쇠가 두 종류인 이유

```
tag     III 재무에 관한 사항.  원문 XML 의 XBRL 분류 코드(aclass)
title   나머지 11개 대분류.   번호·공백을 뗀 제목
```

`III` 만 태그를 쓴다. 나머지 대분류에는 `aclass` 가 아예 없다.

`III` 에서 태그를 쓰는 이유는 같은 항목을 회사마다 다르게 부르기 때문이다.

```
NT_C_D818000   60곳 · 제목 42가지 · 경로 17개
               특수관계자거래 · 특수관계자 · 특수관계자와의거래 · 특수관계자등과의거래 …
```

제목으로 세면 이 넷이 15곳 · 19곳 … 으로 흩어져 전부 문턱 아래로 떨어진다.
태그로 묶으면 60곳이 된다.

`이름가짓수` 가 큰 것이 이런 경우다. `다른제목` 을 보면 무엇이 묶였는지 안다.

```
NT_S_D825705   56곳 · 이름 34가지 · 경로 14개   종속기업, 관계기업 및 공동기업 투자
   다른 이름   종속기업, 관계기업 및 공동기업투자 / 종속기업, 공동기업 및 관계기업투자 / 종속기업투자

NT_S_D831155   56곳 · 이름 26가지 · 경로 24개   고객과의 계약에서 생기는 수익
   다른 이름   수익 / 매출액 / 영업수익
```

`다른제목` 은 태그가 잘못 묶었는지 보는 데도 쓴다. 뜻이 다른 이름이 섞여
있으면 그 태그는 과하게 묶은 것이다. 보이면 `메모` 에 적어 달라.

작업 대상 165행 중 `tag` 111개 · `title` 54개다.

### 규모를 보는 칸

| 칸 | 무엇인가 |
|---|---|
| `기업수` | 70곳 중 몇 곳이 이 절을 갖고 있나 |
| `절수` | 그 절이 문서 전체에서 몇 개인가 |
| `글자수` | 그 절들의 글자 합 |
| `경로수` | 이 절이 몇 가지 경로에 흩어져 있나 |
| `경로` | 어느 경로에 몇 개씩. `III/3/13:11` 은 그 경로에 11절 |

`경로수` 가 크면 회사마다 번호가 다르다는 뜻이다. 주석이 그렇다.

`절수` 는 대개 `기업수` 와 같다. 정정본을 최신 한 건만 쓰기 때문이다. 다른
행이 69개 있는데 한 문서 안에 같은 절이 두 번 나오는 경우다. `사업의 개요` 가
69곳에 72절인 것은 제조업과 금융업 서식을 둘 다 가진 겸업사 때문이다.

### 낱말 칸

| 칸 | 무엇인가 |
|---|---|
| `낱말수` | 뽑힌 낱말 개수. 상한 20 |
| `terms` | 낱말 목록. 공백 구분 |
| `scores` | `낱말:점수`. 그 절이 이 낱말을 얼마나 많이 갖고 있나 |
| `확률` | `낱말:확률`. 이 낱말이 나오면 이 절일 확률 |
| `top_score` | `scores` 중 최고값 |

#### 점수와 확률은 방향이 반대다

```
점수     이 절이 이 낱말을 얼마나 갖고 있나      절 → 낱말
확률     이 낱말이 나오면 이 절일 확률          낱말 → 절
```

질의에서 낱말을 보고 절을 고르는 것이므로 판정에는 `확률` 이 더 가깝다.

```
I  회사의개요    신규연결:117.6(100%)  연결제외:113.2(96%)  중견:99.6(85%)
II 사업의개요    부문:7.0(6%)  사업:4.0(3%)  시장:3.7(3%)
```

앞은 믿을 만하고 뒤는 어느 낱말도 그 절을 특정하지 못한다.

#### 점수 크기를 pathmap.csv 와 비교하지 마라

```
같은 '신규연결'    pathmap.csv 42.4    section_schema.csv 117.6
```

점수가 `(그 절 비율) ÷ (전체 비율)` 이라 분모가 다르면 값이 달라진다.
`pathmap` 은 3,561절 기준이고 이 표는 9,877절 기준이라 2.77배다.
같은 표 안에서만 비교한다.

## 알려진 잡음

낱말에 숫자나 한 글자가 섞여 있다. 작업 대상 낱말 2,405개 중 69개(2.9%)다.

```
숫자만        51개   100 · 16 · 2021 · 2024 · 25
영문 한 글자    9개   A · B · c · b · a
숫자 섞임      9개   제1 · 제542 · 제1107
```

형태소 분석기가 표의 숫자를 낱말로 잡은 것이다. `뺄것` 칸에 적어 주면 된다.
질의에 이런 것이 나올 일이 없으므로 판정이 쉽다.

## 어디부터 보면 좋은가

### 낱말이 적은 것 — 사람이 채워야 하는 자리

```
47곳  5. 재무위험관리 (연결)      낱말 2개   금융자산 공정가치
51곳  19. 충당부채 (연결)        낱말 3개   기타충당부채 충당부채 충당
26곳  7. 사용제한 금융상품 (연결)   낱말 4개   제한 설명 금융자산 사용
```

기업 수는 많은데 낱말이 적다. 회사마다 서술이 달라 공통 낱말이 안 나온 경우다.

### 확률이 낮은 것 — 지금 낱말이 약한 자리

`II 사업의개요` 가 대표다. 확률이 3~6% 라 어느 낱말도 그 절을 특정하지 못한다.
채점 사례 37건 중 12건이 이 절을 노리는데 자동 추출로는 여기가 한계다.

### 판정 기준

`뺄것` 은 이 질문 하나로 정한다.

```
이 낱말이 질의에 나왔을 때, 반드시 이 절을 봐야 하는가
```

`더할것` 은 반대 방향이다.

```
이 절을 묻는 질의에 어떤 말이 나올까
```

절의 본문에서 출발하는 편이 낫다. 평가 질의를 보고 만들면 그 질의에만
맞춰지고 심사에서 다른 것을 물으면 안 잡힌다.

## 다시 만들려면

```bash
python scripts/build_section_schema.py
```

`뺄것` · `더할것` · `메모` 를 채운 뒤에 다시 돌리면 그 내용이 날아간다.
채우기 시작하면 다시 만들지 않는다.

상수는 스크립트 맨 위에 있다.

```
MIN_CHARS  300   이 아래는 빈 껍데기라 뺀다
MIN_CORP     5   작업 대상 문턱
MIN_COVER  0.7   그 절의 70% 이상에 나와야 낱말 후보
MIN_DF       5   전체에서 5개 절 이상에 나와야 한다
MIN_SCORE  3.0   이 아래면 그 절만의 낱말이 아니다
TOP_N       20   절당 낱말 상한
```

## 아직 안 한 것

이 표는 아직 검색에 안 물려 있다. `src/retrieval.py` 는 여전히
`data/eval/pathmap.csv` 를 본다. 표를 채운 뒤에 코드를 고친다.

그때 `PATH_MIN = 15.0` 을 다시 재야 한다. 위에 적은 대로 점수 스케일이
2.77배 다르기 때문이다.
