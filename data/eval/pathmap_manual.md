# 2. 어떻게 만들었나

`ONBOARDING.md` 8.5 의 다섯 걸음을 밟았다. 3단계에서 낱말을 고를 때 눈대중이
아니라 재서 골랐다.

```
1  절 본문을 읽는다              원문 XML 을 목차로 잘라 읽었다
2  그 절로 와야 할 질의를 적는다    평가 질의가 아니라 일반적 표현으로
3  질의를 형태소로 쪼갠다          src/search.py 의 tokenize 를 그대로 썼다
4  낱말마다 변별력을 잰다          아래 3절
5  점수를 매기고 시뮬레이션한다      guess_paths 를 그대로 옮겨 돌렸다
```

## 왜 재서 골랐나

`pathmap_review.md` 에 적힌 `이유` 사고를 피하기 위해서다. `I/5 정관에 관한
사항` 에 `이유` 가 21.3점으로 들어가 실적 질의가 정관 절로 끌려갔다.
사람이 넣는 낱말도 같은 일을 낼 수 있다.

# 3. 변별력을 어떻게 쟀나

`pathmap.csv` 의 점수 정의를 그대로 썼다.

```
점수 = (그 절에 나오는 비율) ÷ (전체 절에 나오는 비율)
```

대상은 2025 사업보고서 비금융 30개사를 목차로 자른 3,789절이다.
같은 자를 쓰는지 온보딩 기재값과 대조했다.

| 낱말 | 이 측정 | 온보딩 4번 답 |
|---|---:|---:|
| 실적 | 10.1% | 9.7% |
| 부문 | 12.9% | 12.9% |
| 개요 | 3.9% | 5.4% |
| 사업 | 27.3% | 39.8% |
| 회사 | 37.4% | 45.3% |

앞의 셋은 근접하고 뒤의 둘이 낮다. 표본이 30개사 사업보고서뿐이고 온보딩은
전체 절 108,337개 기준이라 그렇다. 순위를 매기는 데는 지장이 없다고 봤다.

## 딴 데 몰리는 절을 함께 봤다

전체 출현율이 낮아도 다른 데 더 몰리면 쓰면 안 된다. 실제로 그런 것이 많았다.

```
사업부문   II/1 60%   그런데 VIII/1 80% · II/3 69%
영위      II/1 60%   그런데 I/5 97%          정관에 "영위" 가 많다
요인      IV 29.8%   그런데 IV/1 이 90%      IV/1 행에 이미 16.5 로 있다
영업이익   IV 25.6%   그런데 VII 38%
```

이런 낱말은 점수를 낮추거나 뺐다.

충돌 판정은 `pathmap.csv` 에 행이 있는 절만 대상으로 했다. `III/2` · `III/4` ·
`III/5` 는 행이 없어 `guess_paths()` 에서 경쟁하지 않는다.

## IV 는 장 전체로 봤다

`IV` 는 소절이 여섯이지만 하나의 주제를 다루므로 장 전체를 한 덩어리로 놓고
변별력을 쟀다. 168절이 대상이다. 이렇게 보면 다른 장에 안 밀리는 낱말이 나온다.

```
전년 12.2 · 요인 8.9 · 원인 7.0 · 대비 6.6 · 전망 4.4 · 증감 4.1
```

다만 `전년` `증감` `대비` `요인` 은 `IV/2` `IV/3` `IV/4` `IV/1` 행에 이미
들어 있어 넣지 않았다. 같은 낱말을 두 곳에 높은 점수로 두면 상위 2개가
그 둘로 채워져 다른 정답이 밀려난다 (`ONBOARDING.md` 8.6).

그래서 `IV` 행에는 소절 행에 없는 낱말만 넣었다.

# 5. 넣어야 할 코드 변경 하나

`IV` 행은 지금 코드로는 효과가 없다. 층 2 가 `IV` 를 짚는 것까지는 되는데
부스트가 안 걸린다.

## 무엇이 어긋나는가

경로를 다루는 두 곳의 방식이 다르다.

```
search.candidates()   AND (s.path = ? OR s.path LIKE ?)    접두 일치
retrieval.py 226행    path in want                         완전 일치
```

`IV` 자체는 제목 줄이라 본문이 0자다. 69건 중 67건이 그렇고 나머지 둘도
최대 102자다. `candidates()` 가 `char_len >= 100` 으로 거르므로 `IV` 조각은
거의 후보에 없다. 내용은 전부 `IV/1` ~ `IV/6` 에 있다.

그래서 `guess_paths()` 가 `IV` 를 돌려줘도 `path in want` 로는 당길 조각이 없다.

## 고치는 방법

`src/retrieval.py` 226행을 접두 일치로 바꾸면 된다.

```python
# 지금
hit = [i for i in order if cp.byid[cp.ids[i]]["path"] in want]

# 바꾸면
hit = [i for i in order
       if any(cp.byid[cp.ids[i]]["path"] == w
              or cp.byid[cp.ids[i]]["path"].startswith(w + "/") for w in want)]
```

이러면 `IV` 를 짚었을 때 `IV/1` ~ `IV/6` 조각이 함께 당겨진다.
`search.candidates()` 가 이미 같은 방식이므로 두 곳의 규칙이 맞춰진다.

검색 코드는 `src/retrieval.py` 한 곳에서만 고친다는 협업 규칙이 있어
이쪽에서 고치지 않고 제안만 남긴다.

## 채점도 함께 봐야 한다

`grade()` 는 절 제목의 부분 일치로 채점한다.

```python
return [h.rank for h in hits if any(g in h.title for g in gold)]
```

정답이 `IV. 이사의 경영진단 및 분석의견` 인데 실제로 걸리는 절은 `IV/3` 이고
제목이 `3. 재무상태 및 영업실적` 이라 문자열이 안 겹친다. 접두 일치를 넣어
조각을 당겨도 채점에서 틀림으로 셀 수 있다.

`grade()` 도 경로 기준으로 바꾸거나, 정답을 `IV/2` · `IV/3` 으로 적는 방법이 있다.
어느 쪽이든 평가 기준을 바꾸는 일이라 합의가 필요하다.

# 6. 못 잡는 것

## 6-1. `이유` 가 정관 절을 끌어당긴다

```
질의   "실적 변화를 설명해주고 공시 안에서 그 이유를 찾아줘"
짚음   I/5 정관에 관한 사항  21.3
```

`pathmap_review.csv` 가 겨냥하는 그 건이다. 그쪽에서 `이유` 를 빼면 풀린다.
이 표로는 못 푼다. 같은 낱말에 더 높은 점수를 주는 것은 8.6 위반이다.

## 6-2. 형태소가 갈라 놓는 것

```
"실적이 왜 이렇게 변했는지"   →  ['실적', '이렇', '변하']
"경영진단 의견"              →  ['경영', '진단', '의견']
```

`경영진단` 과 `분석의견` 은 한 낱말로 남지 않는다. 그리고 IV장 168절에서
`경영진단` 0.0% · `분석의견` 0.0% 다. 본문에 아예 없는 말이라 BM25 로는
찾을 수 없고 경로표만이 길이다.

`변하` 는 IV장에 0% 다. 넣을 근거가 없어 안 넣었다. 그래서
"실적이 왜 이렇게 변했는지" 는 `실적` 8.0 만 남아 문턱을 못 넘는다.
층 4 용어 확장의 몫이다.

## 6-3. `II/1` 의 한 유형

`"어떤 사업을 하는 회사인지"` 는 남는 낱말이 `사업` `회사` 둘뿐이고 둘 다
전체 절의 27~37% 에 나온다. 점수를 올리면 그 낱말이 든 모든 질의가 끌려간다.
`ONBOARDING.md` 4번 답에 이미 적힌 한계다.
