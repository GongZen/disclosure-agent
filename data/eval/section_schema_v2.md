25개사 III 계열 제목 2,520개로 네 방식을 견줬다. 한글로 시작하지 않으면
잔재로 봤다.

| 방식 | 잔재 | 새로 망가뜨림 |
|---|---:|---:|
| 지금 `NUM` | 46 | — |
| 첫 온점까지 자르기 | 38 | `11.1 사용권자산` 계열 |
| 숫자시작 + 8자 이내 | 32 | 38건 |
| 번호 덩어리 통째로 | 6 | 0건 |

마지막을 썼다.

```python
# 지금
NUM = re.compile(r"^\s*[\(\[]?\s*[0-9IVXivx]+[\-\.0-9]*\s*[\)\].]?\s*")

# 바꾼 것
NUM = re.compile(r"^\s*[\(\[]?\s*[0-9IVXivx][0-9A-Za-z\-&,.]*[\s\)\].]*")
```

남은 6건은 `[채무증권 발행실적]` 처럼 애초에 번호가 없는 제목이다.

## 1-6. 앞에 붙은 `주석 -` 과 뒤에 붙은 `- 연결` 도 뗐다

```

```

재무제표인지를 나타낼 뿐이다. 둘 다 항목 이름이 아니므로 떼고 판단한다.

```python
_HEAD_NOTE = re.compile(r"^\s*주석\s*[-–.]?\s*")
_TAIL_CS   = re.compile(r"[-–(\[]\s*(연결|별도|개별)\s*[)\]]?\s*$")
```

# 2. KB금융을 어느 판본으로 넣을 것인가

`section_schema.csv` 에 KB금융의 절이 하나도 없다. 이 표에는 넣었다.
넣는 과정에서 판단을 두 번 바꿨으므로 경위를 남긴다.

## 왜 빠졌나

```
KB금융 2025 사업보고서   판본 셋
   20260313001191   원본       xml        절 151 (300자↑ I~XII)
   20260324000835   중간 정정   xml        절 151
   20260619000667   최종 정정   pdf+html   절 143 (PDF 를 잘라야 나온다)

latest_docs()               맨 아래 PDF 를 최신으로 고름
build_section_schema.py     그 PDF 에서 절을 못 뽑아 KB금융이 통째로 빠짐
```

## 검색 색인에는 들어가 있다

처음에 "검색이 보는 `section` · `chunk` 에 KB금융 2025 사업보고서가 없다"
고 적었는데 그것은 틀렸다. `build_section.py` 는 최신본만 고르지 않는다.

```sql
WHERE doc_group='periodic' AND file_format='xml'
```

정기공시 XML 을 전부 읽으므로 위 XML 두 판본이 다 들어간다.
`DECISIONS.md` 2026-08-19 항의 임베딩 묶음에도 KB금융이 조각 7,032개로
가장 많은 회사로 적혀 있다.

빠진 것은 6월 정정분뿐이고, 그 재무 수치는 `data/manual/` 수작업 입력으로
따로 채워져 있다.

## 그래서 XML 로 넣었다

이 표는 검색이 보는 것을 설명하는 표다. 색인에 XML 이 들어 있으면 표도
XML 을 기준으로 삼는 편이 맞다. 최신 XML 인 20260324 정정본을 썼다.

PDF 대신 XML 을 쓰니 두 가지가 저절로 풀렸다.

첫째, `aclass` 가 붙는다. PDF 에는 없어서 제목으로 억지로 맞춰야 했다.

```

```

`DX` 는 은행지주 계열이다. KB금융이 신한지주 · 우리금융지주 · 하나금융지주와
같은 자리에 붙는다.

둘째, PDF 제목이 만들던 1곳짜리 군더더기 행이 사라지고 기존 행에 흡수됐다.

## PDF 자르는 코드는 남겨 둔다

PDF 를 책갈피(outline)로 자르는 코드를 만들어 두었다. 지금 표에는 안 쓰지만
6월 정정본을 색인에 넣기로 하면 그때 필요하다.

처음에는 앞 다섯 쪽의 목차 글자를 긁어 본문에서 제목을 순서대로 찾았다.
제목이 본문 안에 참조로 다시 나오면 그 자리를 절 시작으로 잡는다.

```
9. 종속기업투자   목차 긁기   "… 상각후원가측정대출채권 0 0 0 360,000 (946) …"
                          바로 앞 절인 8. 상각후원가 측정 대출채권 의 표다
9. 종속기업투자   책갈피     "당기말 현재 회사의 종속기업 현황은 다음과 같습니다.
                          회사명 … ㈜국민은행 은행 및 외국환업 대한민국 …"
```

이 PDF 는 책갈피에 제목 · 쪽번호 · 쪽 안의 y 좌표가 다 들어 있다.
글자를 긁을 이유가 없었다. 두 방법으로 각각 자른 뒤 절마다 낱말을 견줬다.
300자 이상 143절 기준이다.

| 겹침 | 절 | 뜻 |
|---|---:|---|
| 90% 이상 | 81 | 사실상 같다 |
| 70~90% | 31 | 경계가 조금 밀렸다 |
| 30~70% | 20 | 내용이 절반쯤 섞였다 |
| 30% 미만 | 11 | 다른 절의 내용이다 |

31절이 크게 어긋났고 그중 4절은 아예 비어 있었다.

```
1. 지배기업의 개요 및 보고주체 (연결)    0자 → 1,113자
1. 회사의 개요 및 보고주체            0자 →   976자
36. 기타포괄손익누계액 (연결)          0자 → 1,268자
16-A. 리스-사용권자산 (연결)          0자 →   331자
```

`pymupdf` 를 쓴다. 앞 방법은 `pypdf` 였다.

# 3. 만들면서 확인한 것

## 3-1. `aclass` 는 제목 뒤가 아니라 앞에 있다

원문 구조가 이렇다.

```xml
<TABLE-GROUP ACLASS="{XBRL}NT_C_D822100">
  <TITLE>10. 유형자산 (연결)</TITLE>
  ...
</TABLE-GROUP>
```

`TABLE-GROUP` 이 `TITLE` 을 감싼다. 제목 뒤에서 찾으면 다음 절의 코드가
붙어 한 칸씩 밀린다.

```
잘못 붙이면   10. 유형자산 → NT_C_D823180 (무형자산 코드)
바르게        10. 유형자산 → NT_C_D822100
```

이쪽 추출기에서 겪은 것이고 `section_schema.csv` 는 정상이다. 대조해 확인했다.

## 3-2. 첨부 파일은 감사보고서다

사업보고서 폴더의 `_00760.xml` `_00761.xml` 은 감사보고서다.
`NT_*` 코드는 본문 파일에만 있다.

```
20260310002820.xml         7,729,056자   NT 코드 66종
20260310002820_00760.xml     566,118자   NT 코드  0종
20260310002820_00761.xml     683,653자   NT 코드  0종
```

첨부를 함께 읽으면 목차 체계가 다른 절이 섞여 단위가 오염된다.
`doc_group='audit'` 로 떼어낸 이유와 같다.

# 4. 칸 설명

`section_schema.csv` 와 같고 두 칸이 늘었다.

| 칸 | 무엇인가 |
|---|---|
| `병합열쇠수` | 이 행이 묶은 열쇠 개수. 1이면 안 묶인 것 |
| `병합열쇠` | 묶인 열쇠 전부. 검색 코드가 대조할 때 이 목록을 쓴다 |

나머지는 기존과 같다.

```
작업대상 · 대분류 · 열쇠 · 열쇠뜻 · 다른제목 · 이름가짓수 · 열쇠종류
기업수 · 절수 · 글자수 · 경로수 · 경로 · 낱말수 · 낱말 · top_score
AI남길것 · AI애매 · AI뺄것 · AI근거
뺄것 · 더할것 · 메모
```

`열쇠` 칸은 열쇠가 하나면 그 열쇠를, 여럿을 묶었으면 정규화한 이름을 담는다.
묶인 열쇠 전부는 `병합열쇠` 를 봐야 한다.

## 값이 기존 표와 맞는지 대조했다

같은 자를 쓰는지 확인한 것이다.

```
회사의 개요       신규연결 100% · 연결제외 96%        기존 표와 같다
정관에 관한 사항    해당주총명 100% · 정관변경일 100%    같다
사업의 개요       부문 5.6:5%                      기존 부문 7.0:6% 과 근사
```

## 낱말이 약한 자리

```
기타금융부채       top 3.5
금융상품          top 5.0
사업의 개요        top 5.6
담보제공자산       top 8.9
```

`사업의 개요` 가 여전히 약하다. 병합으로도 안 풀리는 자리이고 층 4 용어 확장이
필요한 곳이다. 낱말이 0개인 작업 대상 행은 없다.

# 5. 아직 안 한 것

## `뺄것` · `더할것` · `메모` 는 비어 있다

`AI*` 칸만 채웠다. 사람 판정은 그다음이다.

## 검색에 안 물려 있다

`src/retrieval.py` 는 `pathmap.csv` 를 본다. 이 표도 `section_schema.csv` 와
같은 처지다.

다만 이 표는 한 행이 여러 열쇠를 묶으므로 대조 규칙이 하나 늘어난다.

```
열쇠종류 tag     조각의 aclass 가 병합열쇠 중 하나와 일치
열쇠종류 title   조각 제목을 정규화해 열쇠와 일치
```

`열쇠뜻` 에 붙인 `(주석)` · `(재무제표)` 는 사람이 읽기 위한 표시다.
대조에 쓰는 값이 아니므로 코드가 볼 때는 떼야 한다.

## 코드가 저장소에 없다

이 표를 만든 코드는 임시 작업 폴더에 있다. `scripts/build_section_schema.py` 에
1-5 · 1-6 · 1-7 을, `scripts/prejudge_schema.py` 에 파일명 인자를 반영하는 편이
낫다고 본다. 그러면 코드가 한 곳에 남는다.
