# 1. 무엇이 달라졌나

```
              작업대상 행   III   III 밖
section_schema     165   123      42
v2                 127    84      43
```

`III` 이 39행 줄었다. 32% 다. 둘을 고친 결과다.

## 1-1. 연결과 별도를 한 단위로 묶었다

같은 항목의 연결본과 별도본이 서로 다른 열쇠로 갈라져 있었다.

```
NT_C_D822100   유형자산 (연결)   60곳
NT_S_D822105   유형자산          60곳
```

숫자까지 다르므로 `C` 와 `S` 만 떼어서는 안 묶인다. 그래서 접두(`NT`)와
정규화한 이름이 같으면 한 단위로 본다.

연결이냐 별도냐는 답변할 때 밝힐 사항이지, 그 절이 무엇을 담고 있는지는
같다. 낱말도 거의 같았다.

```
NT_C_D822100   낱말 20개   top 34.1
NT_S_D822105   낱말 20개   top 34.8
```

같은 낱말을 두 번 판정하는 셈이라 작업량이 그만큼 낭비된다.

49행이 186개 열쇠를 묶었다. 어느 코드가 묶였는지는 `병합열쇠` 칸에 남겼다.

```
무형자산 (연결)    9개   NT_C_D823180 · NT_S_D823185 · NT_C_D832410 · NT_C_DI824000 …
유형자산 (연결)    8개   NT_C_D822100 · NT_S_D822105 · NT_C_DI821000 · NT_C_DS812000 …
```

### 아직 정하지 않은 것

지금 규칙은 "접두와 이름이 같으면 묶는다" 라 C/S 짝보다 넓다.

```
NT_C_D822100 · NT_S_D822105      C/S 만 다름          묶는 것이 확실하다
NT_C_D822100 · NT_C_DS812000     둘 다 C. 숫자가 다름   판단이 필요하다
```

`DS` · `DI` · `DX` 는 업종별 서식 계열로 보인다. 이름이 같으니 묶는 편이
자연스러워 보이나 확인하지 못했다. 좁게 가야 한다면 행이 늘어난다.

## 1-2. 번호 떼는 규칙을 고쳤다

일부 회사가 `10-A.` `10&11.` `4,5.` 처럼 번호를 붙인다. 지금 정규식은 이걸
못 떼고 잔재를 남긴다.

```
6-A. 금융자산과 금융부채-공정가치     →   A. 금융자산과 금융부채-공정가치
10&11. 상각후원가 측정 대출채권       →   &11. 상각후원가 측정 대출채권
4,5. 금융위험관리 및 자본관리         →   ,5. 금융위험관리 및 자본관리
```

25개사 III 계열 제목 2,520개로 세 방식을 견줬다. 한글로 시작하지 않으면
잔재로 봤다.

| 방식 | 잔재 | 새로 망가뜨림 |
|---|---:|---:|
| 지금 `NUM` | 46 | — |
| 첫 온점까지 자르기 | 38 | `11.1 사용권자산` 계열 |
| 숫자시작 + 8자 이내 | 32 | 38건 |
| 번호 덩어리 통째로 | 6 | 0건 |

마지막을 썼다. 정규식 한 줄이다.

```python
# 지금
NUM = re.compile(r"^\s*[\(\[]?\s*[0-9IVXivx]+[\-\.0-9]*\s*[\)\].]?\s*")

# 바꾼 것
NUM = re.compile(r"^\s*[\(\[]?\s*[0-9IVXivx][0-9A-Za-z\-&,.]*[\s\)\].]*")
```

남은 6건은 `[채무증권 발행실적]` 처럼 애초에 번호가 없는 제목이라 손댈 것이 없다.

# 2. KB금융이 빠져 있었다

`section_schema.csv` 에 KB금융의 절이 하나도 없다. 이 표에는 넣었다.

## 왜 빠졌나

```
KB금융 2025 사업보고서 최신본   20260619 정정본 · pdf+html
build_section.py             WHERE file_format='xml'    → 절 0개
latest_docs()                그 PDF 를 최신으로 고름
결과                         section 이 없어 스키마에서 통째로 빠짐
```

`file_format` 이 `xml` 이 아닌 정기공시가 셋이다.

```
KB금융          20260619  [기재정정]사업보고서 (2025.12)   pdf+html
한화에어로스페이스   20260513  분기보고서 (2026.03)          pdf+html
한화오션          20240514  [기재정정]분기보고서 (2024.03)   pdf+html
```

2025 사업보고서에 걸리는 것은 KB금융 하나다. 나머지 둘은 분기보고서라
이 표의 대상이 아니다.

## 어떻게 넣었나

PDF 1,085쪽을 목차 제목으로 잘랐다. 176절이 나왔고 300자 이상이 143절이다.
경로도 `I/1` `II/2` 처럼 정상으로 붙는다.

```
II/2   2. 영업의 현황              139,889자
II/5   5. 재무건전성 등 기타 참고사항   58,671자
I/2    2. 회사의 연혁              33,363자
```

`aclass` 는 PDF 에 없으므로 KB금융의 `III` 절은 제목 쪽으로 떨어진다.

그리고 `6-A.` `10&11.` 같은 번호가 전부 KB금융에서 나온 것이다. 1-2 가
겨냥한 문제와 같은 뿌리다.

## 근본 해결은 따로 필요하다

이 표는 PDF 를 읽어 메웠지만, 검색은 여전히 `section` · `chunk` 를 본다.
그쪽에 KB금융 2025 사업보고서가 없으면 질의가 와도 조각이 없다.

`build_section.py` 가 PDF 를 읽게 하거나, `latest_docs()` 가 XML 이 있는
판본을 고르게 하거나 둘 중 하나가 필요하다. 뒤쪽이면 20260313 원본을 쓰게 된다.

# 3. 만들면서 확인한 것

## 3-1. `aclass` 는 제목 뒤가 아니라 앞에 있다

원문 구조가 이렇다.

```xml
<TABLE-GROUP ACLASS="{XBRL}NT_C_D822100">
  <TITLE>10. 유형자산 (연결)</TITLE>
  ...
</TABLE-GROUP>
```

`TABLE-GROUP` 이 `TITLE` 을 감싼다. 제목 뒤에서 찾으면 다음 절의 코드가
붙어 한 칸씩 밀린다.

```
잘못 붙이면   10. 유형자산 → NT_C_D823180 (무형자산 코드)
바르게        10. 유형자산 → NT_C_D822100
```

이쪽 추출기에서 겪은 것이고 `section_schema.csv` 는 정상이다.
대조해 확인했다. 같은 것을 다시 만들 때를 위해 적어 둔다.

## 3-2. 첨부 파일은 감사보고서다

사업보고서 폴더에 `_00760.xml` `_00761.xml` 이 있는데 감사보고서다.
`NT_*` 코드는 본문 파일에만 있다.

```
20260310002820.xml         7,729,056자   NT 코드 66종
20260310002820_00760.xml     566,118자   NT 코드  0종
20260310002820_00761.xml     683,653자   NT 코드  0종
```

첨부를 함께 읽으면 목차 체계가 다른 절이 섞여 단위가 오염된다.
`doc_group='audit'` 로 떼어낸 이유와 같다.

# 4. 칸 설명

`section_schema.csv` 와 같고 두 칸이 늘었다.

| 칸 | 무엇인가 |
|---|---|
| `병합열쇠수` | 이 행이 묶은 열쇠 개수. 1이면 안 묶인 것 |
| `병합열쇠` | 묶인 열쇠 전부. 검색 코드가 대조할 때 이 목록을 쓴다 |

나머지는 기존과 같다.

```
작업대상 · 대분류 · 열쇠 · 열쇠뜻 · 다른제목 · 이름가짓수 · 열쇠종류
기업수 · 절수 · 글자수 · 경로수 · 경로 · 낱말수 · 낱말 · top_score
뺄것 · 더할것 · 메모
```

`낱말` 은 `낱말:점수:확률` 을 공백으로 이어 붙인 것이다. 기존과 같다.

## 값이 기존 표와 맞는지 대조했다

같은 자를 쓰는지 확인한 것이다.

```
회사의 개요       신규연결 100% · 연결제외 96%        기존 표와 같다
정관에 관한 사항    해당주총명 100% · 정관변경일 100%    같다
사업의 개요       부문 5.6:5%                      기존 부문 7.0:6% 과 근사
```

`사업의 개요` 가 여전히 가장 약하다. 낱말 4개에 top 5.6 이다. 병합으로도
안 풀리는 자리이고 층 4 용어 확장이 필요한 곳이다.

## 낱말이 0개인 행은 없다

기존 표에서 `우발부채` 같은 것이 0개였는데 병합으로 표본이 늘어 해소됐다.
