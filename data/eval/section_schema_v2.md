## 1-1. 연결과 별도를 한 단위로 묶었다

같은 항목의 연결본과 별도본이 서로 다른 열쇠로 갈라져 있었다.

```
NT_C_D822100   유형자산 (연결)   60곳
NT_S_D822105   유형자산          60곳
```

숫자까지 다르므로 `C` 와 `S` 만 떼어서는 안 묶인다. 그래서 접두(`NT`)와
정규화한 이름이 같고, 그 안에 `C` 와 `S` 가 함께 있으면 한 단위로 본다.

연결이냐 별도냐는 답변할 때 밝힐 사항이지, 그 절이 무엇을 담고 있는지는 같다.
낱말도 거의 같았다.

112행이 336개 열쇠를 묶었다. 어느 코드가 묶였는지는 `병합열쇠` 칸에 있다.

```
무형자산     9개   NT_C_D823180 · NT_C_D832410 · NT_C_DI824000 · NT_C_DS815000 …
유형자산     8개   NT_C_D822100 · NT_C_DI821000 · NT_C_DS812000 · NT_S_D822105 …
충당부채     8개   NT_C_D827570 · NT_C_DI832000 · NT_C_DS821000 · NT_S_D827575 …
```

### 아직 정하지 않은 것 둘

지금 규칙은 "접두와 이름이 같고 C·S 가 둘 다 있으면 묶는다" 라 C/S 짝보다 넓다.

```
NT_C_D822100 · NT_S_D822105     C/S 만 다름          묶는 것이 확실하다
NT_C_D822100 · NT_C_DS812000    둘 다 C. 숫자가 다름   판단이 필요하다
```

`DS` · `DI` · `DX` 는 업종별 서식 계열로 보인다. 이름이 같으니 묶는 편이
자연스러워 보이나 확인하지 못했다.

이름이 거의 같은데 안 묶이는 짝도 있다.

```
NT_S_D825705   56곳   종속기업, 관계기업 및 공동기업 투자
NT_S_D825485    5곳   종속기업, 관계기업 및 공동기업 투자자산
```

본문이 둘 다 지분법 투자의 변동내역이다. 이름 끝에 `자산` 이 붙느냐 차이뿐인데
정규화 이름 완전일치라 안 묶인다. 이런 짝을 전수로 훑어 별칭 목록을 만들 수 있다.

## 1-2. 재무제표 본체도 묶었다

주석만 묶고 본체는 두었더니 본체가 여덟 행으로 흩어져 있었다. 본체는 글이 아니라
표이고 연결본과 별도본의 담긴 내용도 같으므로 같은 규칙을 적용했다.

```
재무상태표        70곳   BS_C · BS_S
포괄손익계산서     70곳   IS_C1 · IS_C3 · IS_S1 · IS_S3

현금흐름표        70곳   CF_C · CF_S
손익계산서        21곳   IS_C2 · IS_S2
```

앞판에서 "판단이 필요하다" 고 남겨 둔 손익계산서 계열이 여기서 함께 풀렸다.

```
IS_C1   연결 포괄손익계산서   42곳   한 장으로 낸다

`IS_C1` 과 `IS_C3` 은 이름이 같으므로 한 행이 됐다. 합쳐 70곳이다.
`IS_C2` 는 이름이 `손익계산서` 로 달라 따로 남았다. IFRS 가 손익을 제시하는

## 1-3. 이름이 겹치는 행에 성격을 붙였다

병합 뒤 이름만으로는 구별이 안 되는 행이 생겼다. 겹칠 때만 뒤에 표시를 붙였다.

```
현금흐름표 (재무제표)   70곳   CF_C · CF_S            본체
현금흐름표 (주석)      64곳   NT_C_D851100 …         주석
```

다만 겹치는 27조 가운데 본체와 주석이 맞붙은 것은 `현금흐름표` 하나다.
나머지는 태그가 붙은 주석 단위와, 태그 없이 제목만으로 잡힌 소수 단위가
겹친 것이다.

```
법인세비용 (주석)        65곳  O     태그가 붙은 본 단위
법인세비용 (태그 없음)      2곳  -     서식이 달라 태그가 안 붙은 잔여

나머지 잔여 단위는 1~3곳이라 작업 대상이 아니다. `(태그 없음)` 쪽은 뒤에
태그 단위로 흡수할 수 있는지 따로 볼 자리다.

## 1-4. 번호 떼는 규칙을 고쳤다

일부 회사가 `10-A.` `10&11.` `4,5.` 처럼 번호를 붙인다. 앞 정규식은 못 뗀다.

```
6-A. 금융자산과 금융부채-공정가치     →   A. 금융자산과 금융부채-공정가치
10&11. 상각후원가 측정 대출채권       →   &11. 상각후원가 측정 대출채권
4,5. 금융위험관리 및 자본관리         →   ,5. 금융위험관리 및 자본관리
```

25개사 III 계열 제목 2,520개로 네 방식을 견줬다. 한글로 시작하지 않으면
잔재로 봤다.

| 방식 | 잔재 | 새로 망가뜨림 |
|---|---:|---:|
| 지금 `NUM` | 46 | — |
| 첫 온점까지 자르기 | 38 | `11.1 사용권자산` 계열 |
| 숫자시작 + 8자 이내 | 32 | 38건 |
| 번호 덩어리 통째로 | 6 | 0건 |

마지막을 썼다.

```python
# 지금
NUM = re.compile(r"^\s*[\(\[]?\s*[0-9IVXivx]+[\-\.0-9]*\s*[\)\].]?\s*")

# 바꾼 것
NUM = re.compile(r"^\s*[\(\[]?\s*[0-9IVXivx][0-9A-Za-z\-&,.]*[\s\)\].]*")
```

남은 6건은 `[채무증권 발행실적]` 처럼 애초에 번호가 없는 제목이다.

## 1-5. 앞에 붙은 `주석 -` 과 뒤에 붙은 `- 연결` 도 뗐다

번호를 뗀 뒤에도 병합이 안 되는 짝이 남아 있었다.

```

… - 별도                          201건
```

`주석 -` 은 그 절이 주석이라는 표시일 뿐이고, `- 연결` `- 별도` 는 어느 쪽
재무제표인지를 나타낼 뿐이다. 둘 다 항목 이름이 아니므로 떼고 판단한다.

```python
_HEAD_NOTE = re.compile(r"^\s*주석\s*[-–.]?\s*")
_TAIL_CS   = re.compile(r"[-–(\[]\s*(연결|별도|개별)\s*[)\]]?\s*$")
```

# 3. 만들면서 확인한 것

## 3-1. `aclass` 는 제목 뒤가 아니라 앞에 있다

원문 구조가 이렇다.

```xml
<TABLE-GROUP ACLASS="{XBRL}NT_C_D822100">
  <TITLE>10. 유형자산 (연결)</TITLE>
  ...
</TABLE-GROUP>
```

`TABLE-GROUP` 이 `TITLE` 을 감싼다. 제목 뒤에서 찾으면 다음 절의 코드가
붙어 한 칸씩 밀린다.

```
잘못 붙이면   10. 유형자산 → NT_C_D823180 (무형자산 코드)
바르게        10. 유형자산 → NT_C_D822100
```

이쪽 추출기에서 겪은 것이고 `section_schema.csv` 는 정상이다. 대조해 확인했다.

## 3-2. 첨부 파일은 감사보고서다

사업보고서 폴더의 `_00760.xml` `_00761.xml` 은 감사보고서다.
`NT_*` 코드는 본문 파일에만 있다.

```
20260310002820.xml         7,729,056자   NT 코드 66종
20260310002820_00760.xml     566,118자   NT 코드  0종
20260310002820_00761.xml     683,653자   NT 코드  0종
```

첨부를 함께 읽으면 목차 체계가 다른 절이 섞여 단위가 오염된다.
`doc_group='audit'` 로 떼어낸 이유와 같다.

# 4. 칸 설명

`section_schema.csv` 와 같고 두 칸이 늘었다.

| 칸 | 무엇인가 |
|---|---|
| `병합열쇠수` | 이 행이 묶은 열쇠 개수. 1이면 안 묶인 것 |
| `병합열쇠` | 묶인 열쇠 전부. 검색 코드가 대조할 때 이 목록을 쓴다 |

나머지는 기존과 같다.

```
작업대상 · 대분류 · 열쇠 · 열쇠뜻 · 다른제목 · 이름가짓수 · 열쇠종류
기업수 · 절수 · 글자수 · 경로수 · 경로 · 낱말수 · 낱말 · top_score
AI남길것 · AI애매 · AI뺄것 · AI근거
뺄것 · 더할것 · 메모
```

`열쇠` 칸은 열쇠가 하나면 그 열쇠를, 여럿을 묶었으면 정규화한 이름을 담는다.
묶인 열쇠 전부는 `병합열쇠` 를 봐야 한다.

## 값이 기존 표와 맞는지 대조했다

같은 자를 쓰는지 확인한 것이다.

```
회사의 개요       신규연결 100% · 연결제외 96%        기존 표와 같다
정관에 관한 사항    해당주총명 100% · 정관변경일 100%    같다
사업의 개요       부문 5.6:5%                      기존 부문 7.0:6% 과 근사
```

## 낱말이 약한 자리

```
기타금융부채       top 3.6
금융상품          top 5.0
사업의 개요        top 5.6
담보제공자산       top 8.8
```

`사업의 개요` 가 여전히 약하다. 병합으로도 안 풀리는 자리이고 층 4 용어 확장이
필요한 곳이다. 낱말이 0개인 작업 대상 행은 없다.

표시다. 대조에 쓰는 값이 아니므로 코드가 볼 때는 떼야 한다.

1-4 · 1-5 · 1-6 을, `scripts/prejudge_schema.py` 에 파일명 인자를 반영하는 편이
낫다고 본다. 그러면 코드가 한 곳에 남는다.
