# 골든 데이터셋 작성 안내

사람이 원문을 직접 읽어 값을 적는 정답지다. 파서를 고칠 때마다 이것과 대조한다.

AI 가 값을 뽑아 채우지 않는다. 화면에 숫자가 이미 적혀 있으면 검증 없이 넘기기 쉽고,
틀린 값이 정답으로 굳으면 정답지가 오히려 해가 되기 때문이다.

---

## 무엇을 적는가

`data/golden/golden_values.csv` 의 빈 칸을 채운다. 20건 × 6항목 = 120행이다.

```
값        원문에 적힌 숫자를 그대로. 쉼표는 있어도 없어도 된다
          음수는 (1,234) 로 적혀 있으면 -1234 로 적는다
단위      표 위의 (단위 : 백만원) 을 그대로. 원 · 천원 · 백만원
회계연도   그 값이 어느 해 것인가. 2025 처럼
기간유형   연간 · 누적 · 3개월      분기·반기 보고서는 두 열이 나란히 있다
비고      값이 없으면 이유를 적는다. 계정 자체가 없음 · 다른 이름으로 있음 등
```

기준은 연결로 통일했다. 별도만 있는 문서면 비고에 적고 별도 값을 넣는다.

## 왜 이 여섯 항목인가

```
자산총계 · 부채총계 · 자본총계    회계 항등식으로 자체 검증이 되는 조합
매출액 · 영업이익 · 당기순이익     손익계산서의 세 단계. 계정 이름이 업종마다 갈리는 축
```

자산총계 = 부채총계 + 자본총계 가 성립하므로, 셋을 적으면 옮겨 적는 실수도 잡힌다.

## 계정 이름이 다르면

업종에 따라 이름이 다르다. 원문에 있는 이름을 비고에 함께 적어달라.

```
매출액 · 영업수익 · 수익(매출액) · 영업수익(보험손익)
자산총계 · 자산합계
부채및자본총계 만 있고 자본총계가 없는 경우도 있다
```

이 기록이 D3(계정 체계 통합) 을 정하는 근거가 된다.

## 채운 방법이 둘이다

| 출처 | 행 | 성격 |
|---|---|---|
| 사람이 원문을 읽음 | 60 | 파서와 완전히 다른 경로. 어떤 오류든 드러난다 |
| XBRL 태그 자동 | 69 | 태그를 읽은 것. 태그가 틀렸으면 같이 틀린다 |
| 빈칸 | 3 | 현대글로비스 손익. 태그에 단위가 없어 채울 수 없다 |

`비고` 칸에 `xbrl 자동` 이라고 적힌 것이 뒤쪽이다.

자동 채움은 `scripts/fill_golden.py` 가 한다. 표 파싱을 쓰지 않는다. 그것을 쓰면
검사받을 것으로 정답지를 만드는 셈이다. 태그 경로만 쓰므로 표 파싱을 검증하는
데는 쓸 수 있고, 태그 경로가 바뀌었을 때 회귀를 잡는다.

## 22건 전부 회계 항등식이 성립한다

`자산총계 = 부채총계 + 자본총계` 가 사람이 채운 것과 자동으로 채운 것 모두에서
맞아떨어진다. 두 방법이 독립이므로 이것이 서로에 대한 확인이 된다.

## 빈칸 3건

현대글로비스 2023년 3분기 보고서의 매출액·영업이익·당기순이익이다. 태그는
붙어 있으나 `ADECIMAL` 이 없어 단위를 모른다. 표 파싱은 제목 표에서 단위를
읽어 값을 내지만, 그것으로 채우면 정답지가 아니게 된다.

사람이 원문을 읽어 채우면 그 문서가 검증 대상이 된다. 지금은 비워둔다.
