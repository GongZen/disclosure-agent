# 데이터 정책

지금 유효한 원칙만 짧게 적는다. 왜 그렇게 정했는지는 `DECISIONS.md` 를 본다.

정책은 미리 다 세우는 것이 아니다. 같은 유형의 판단이 두 번째 나왔을 때
정책으로 올리고, 세 번째부터는 다시 묻지 않는다.

---

## 1. 원문에 없는 값

만들지 않는다. 다만 유도가 명시적이면 만들고 출처를 남긴다.

```
만든다      자본총계 = 부채및자본총계 − 부채총계
            원문에 두 값이 다 있고 관계가 회계 정의로 고정돼 있다
            source 컬럼에 "계산" 을 남기고 답변에서 유도 과정을 밝힌다

안 만든다    추정 · 보간 · 다른 문서에서 가져오기
            그 값은 이 공시의 근거가 아니다

우선순위     같은 값이 다른 표에 원문으로 있으면 그쪽을 먼저 쓴다
            재무상태표에 자본총계가 없어도 자본변동표의 기말 자본이 원문 값이다
```

## 2. 원문의 값 오류

고치지 않고 그대로 담는다. 검산 결과를 컬럼에 남긴다.

모든 답변에 근거 공시를 표시해야 하므로 우리가 고친 값은 근거와 어긋난다.
대신 "공시 기재값과 재계산값이 다릅니다" 를 답변에서 밝힌다.

W4 에서 계약 공시 4건, 지분공시 1건이 이 경우였다.

## 3. 못 뽑은 값

원문에 없어서인지 우리가 못 읽어서인지 구분해 표시한다. D7 네 갈래를 쓴다.

```
out_of_scope     제공 데이터 범위 밖
no_document      해당 공시가 없다
not_disclosed    회사가 안 적었다
extract_failed   우리가 못 읽었다
```

우리가 못 읽은 것을 "기재되지 않았다" 로 답하면 지표 7의 한계 고지가 아니라
지표 4의 거짓 진술이 된다.

## 4. 값의 출처를 남긴다

같은 항목이라도 어디서 왔는지에 따라 신뢰도가 다르다.

```
XBRL 태그      문서가 기계용으로 명시한 값
표 제목        문서가 사람용으로 명시한 이름으로 판정
내용 판정      계정 조합으로 우리가 판정
순서 판정      법정 배열로 우리가 추정. 가장 약하다
계산          원문 값에서 유도
```

답변에서 근거를 댈 때 이 구분이 쓰인다.
