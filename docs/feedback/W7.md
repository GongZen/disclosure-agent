## 측정 코드가 갈라져서 사흘을 잃을 뻔했다

이 작업에서 가장 크게 헤맨 것이다. 검색 기법의 문제가 아니라 재는 도구의
문제였다.

### 무엇이 일어났나

성적을 재는 스크립트를 셋 만들었다. 같은 질의에 서로 다른 답을 냈다.

```
eval_evalset    문항 16 · 20 적중 · 자체제작 5 는 4위
tune_stop       문항 16 · 20 · 자체제작 5 전부 1위
직접 확인        또 다른 결과
```

어느 것이 맞는지 알 수 없었다. 후보 구성과 채점 기준이 조금씩 달랐다.
한 곳은 목차 조각을 후보에 넣고 한 곳은 뺐다. 한 곳은 조각 단위로 채점하고
한 곳은 절 단위로 했다.

### 더 나쁜 일

`STOP` 목록을 바꿔 가며 재는데 어떤 설정에서도 숫자가 같았다.

```
STOP 없음      1위 12 · 8위내 29
STOP 전부      1위 12 · 8위내 29
− 질의동사     1위 12 · 8위내 29
− 연결어       1위 12 · 8위내 29
```

설정이 실제로 안 바뀌고 있다는 뜻인데, 코드를 봐도 바꾸는 줄이 있었다.

사용자가 먼저 지적했다.

> 내가 볼 때는 모든 설정이 동일하다면, RRF나 벡터의 성능 상의 문제가 아니라
> 뭔가 코드가 꼬여서 예전 결과를 계속 반복하여 출력하고 있거나 바꾼 줄 알았지만
> 동일한 설정으로 계속 검증하고 있는 코드 상의 문제라고 판단된다

맞았다. 원인이 둘이었다.

```
1. query.py 가 "보고서" 를 두 곳에서 지우고 있었다
     정규식이 먼저 지우고 STOP 이 또 지운다
     STOP 에서 빼도 정규식이 이미 지워서 효과가 없다

2. eval_evalset.py 에 SyntaxError 가 있었다
     global 선언 위치가 틀려 스크립트가 아예 안 돌았다
     출력은 이전 실행의 것을 보고 있었다
```

### 어떻게 고쳤나

실행을 한 곳에 모았다.

```
src/retrieval.py        후보 구성 · 검색 · 채점. 여기만 고친다
scripts/eval_body.py    설정을 바꿔 가며 부른다. --mode 로 갈래를 늘린다
```

`query.py` 의 정규식은 합성어만 지우게 고쳤다. "사업보고서" 는 지우고
"보고서" 단독은 STOP 에 맡긴다. 같은 낱말을 두 곳에서 지우지 않는다.

### 배운 것

측정 코드를 못 믿으면 무엇을 고쳐도 확인이 안 된다.

검색 기법을 고르는 일은 전부 비교로 결정된다. 벡터가 나은지 BM25 가 나은지,
가중치를 얼마로 둘지, 경로 필터가 효과가 있는지 — 전부 두 숫자를 견줘서 정한다.
견주는 자가 틀리면 결정이 전부 틀린다.

그리고 같은 처리를 두 곳에서 하지 않는다. 한 곳에서만 지우면 그 한 곳만 보면
된다. 두 곳이면 둘 다 봐야 하는데, 보통 하나만 보고 원인을 못 찾는다.

## 목차 조각이 1위를 차지했다

층 3 을 재는데 SK하이닉스 질의에서 엉뚱한 것이 걸렸다.

```
질의   SK하이닉스가 어떤 사업을 하는 회사인지 사업보고서 기준으로 알려줘

1위    목 차                        유사도 0.7274
...
11위   1. 사업의 개요               유사도 0.6432   ← 정답
```

### 왜 그런가

`목 차` 는 그 문서의 절 제목을 전부 나열한 조각이다. 사업의 개요도,
배당에 관한 사항도, 임원의 보수도 거기 다 적혀 있다. 그래서 어떤 질의를
던져도 낱말이 겹친다.

벡터는 의미가 비슷한 것을 찾는 도구다. 제목만 잔뜩 모아 둔 조각은
그 문서의 모든 주제와 조금씩 비슷하다. 정답보다 높게 나오는 게 이상하지 않다.

### 고친 것

후보에서 뺐다. 검색 대상이 아니기 때문이다. 목차를 찾아 줘도 답이 안 나온다.

```python
SKIP_TITLE = re.compile(r"^\s*(목\s*차|【.*확인.*】|전문가의 확인|"
                        r"전문가와의 이해관계)\s*$")
```

【대표이사 등의 확인】 같은 것도 같이 뺐다. 내용이 없는 절이다.

### 결론이 뒤집혔다

이걸 빼기 전에는 BM25 가 벡터보다 낫다고 판정하고 있었다. 빼고 다시 재니
벡터가 나았다. 후보에 쓰레기가 섞여 있으면 그 쓰레기에 잘 걸리는 쪽이
나빠 보인다. 기법의 우열이 아니라 후보의 문제였다.

## 경로 필터 — 개수로 세면 안 된다

층 2 다. 질의가 무엇을 묻는지 알면 볼 절을 좁힐 수 있다.

사업보고서는 법정 서식이라 70개 기업이 같은 경로에 같은 제목을 쓴다.
`I/1 회사의 개요` 부터 `XII 상세표` 까지 60개 남짓이고 기업이 달라도 안 바뀐다.

### 처음에 한 것

절마다 대표 낱말을 뽑아 두고, 질의의 낱말이 몇 개 겹치는지 셌다.
성적이 떨어졌다.

```
경로 없음     12/37
개수로 매칭   10/37    ← 두 건을 잃었다
```

### 왜 떨어졌나

`"주주환원 정책"` 이라는 질의가 `IV/6` 을 짚었다. 그 절의 대표 낱말에
`정책` 이 있었기 때문이다. 정답은 `III/6 배당에 관한 사항` 이었다.

낱말마다 변별력이 다르다. `배당성향` 은 III/6 을 특정하지만 `정책` 은
아무 절이나 가리킨다. 개수만 세면 둘이 같은 한 표다.

### 고친 것

점수를 남기고 합이 문턱을 넘어야 짚게 했다.

```
점수 = (그 절에 나오는 비율) ÷ (전체 절에 나오는 비율)

III/6   배당성향 40.9 · 배당수익률 41.2 · 결산배당 35.4
II/1    부문 3.8                                        이것뿐이다
```

문턱은 15.0 이다. `정책` 하나로는 못 넘는다.

```
경로 없음     1위 12 · 3위내 22 · 8위내 29
경로 적용     1위 14 · 3위내 23 · 8위내 29
```

### 좁히지 않고 올리기만 한다

짚은 경로의 조각을 앞으로 당기되 나머지를 후보에서 빼지 않는다.
잘못 짚으면 정답을 통째로 버리게 되기 때문이다.

`II/1 사업의 개요` 처럼 대표 낱말이 안 잡히는 절이 있다. 내용이 일반적이어서
그 절만의 낱말이 안 나온다. 실측하면 `부문 · 시장 · 사업 · 당사` 같은 흔한
말만 걸린다. 그런 질의는 매핑에 안 걸리고 일반 검색으로 간다. 문턱을 두는
이유가 이것이다. 확신이 없으면 안 짚는다.

### 질의가 아니라 절 본문에서 뽑았다

평가 질의를 보고 매핑을 만들면 그 질의에 맞춰진다. 심사에서 다른 것을 물으면
안 잡힌다. 그래서 절의 본문에서 그 절에만 유난히 많이 나오는 낱말을 뽑았다.

`scripts/build_pathmap.py` 가 만들고 결과는 `data/eval/pathmap.csv` 44행이다.

## 질의 해석기를 넣었더니 성적이 떨어졌다

층 1 이다. 처음 붙였을 때 38% 에서 25% 로 떨어졌다.

### 원인

`STOP` 을 너무 많이 넣었다.

```
질의    삼성전자의 사업부문 구성과 주요 매출처를 알려줘
검색어  ['사업', '회사']       ← 이것만 남았다
```

두 낱말로는 아무것도 못 가린다. 모든 사업보고서에 나오는 말이다.

그리고 `보고서` · `기준` 같은 말이 정답 조각에도 들어 있었다. 버릴 말인 줄
알았는데 단서였다.

### 고친 것

`STOP` 을 갈래로 나누고 갈래마다 켜고 끄며 쟀다.

```
질의동사    알리 · 정리 · 설명 · 확인 · 비교
연결어      기준 · 근거 · 대하 · 관하 · 위하
의문사      얼마 · 무엇 · 어디 · 언제 · 누구
문서종류    보고서 · 공시
일반명사    내용 · 사항 · 경우 · 정도 · 수준
서술어      주세요 · 바랍니다 · 싶다 · 하다
```

`scripts/eval_body.py --mode=stop` 으로 갈래별 성적을 낸다.

### 왜 규칙으로 만들었나

질의를 구조화하는 데 LLM 을 쓸 수도 있었다. 안 썼다.

```
규칙    기업명은 코퍼스에 있는 목록과 대조하면 된다
        연도는 네 자리 숫자다
        문서 종류는 정해진 말이 붙는다
        틀리면 어디가 틀렸는지 보인다

LLM     한 번 더 부르는 비용과 시간이 든다
        같은 질의에 다른 답이 나올 수 있다
        틀려도 왜 틀렸는지 안 보인다
```

평가 질의 28개 중 27개에서 대상 기업을 뽑았다. 규칙으로 충분했다.
못 뽑은 하나는 기업을 아예 안 밝힌 질의다.

## 채점을 절 단위로 한다

조각(chunk) 단위로 채점하다가 절(section) 단위로 바꿨다.

`1. 사업의 개요` 가 조각 열둘로 잘려 있다고 하자. 어느 조각이 걸리든
생성 모델에는 그 절을 넘긴다. 조각은 찾기 위한 단위이고 답을 주는 단위는
절이다. 조각 3번이 아니라 5번이 걸렸다고 틀렸다고 하면 실제 성능보다
낮게 나온다.

정답 절은 사용자가 만든 `EVALSET_SOURCE.md` 에서 옮겼다. AI 가 정답을
정하지 않는다.

### 사람이 만드는 2겹 경로표

지금 `pathmap.csv` 는 데이터에서 뽑은 것이라 `II/1` 처럼 특징 없는 절을
못 짚는다. 목차가 70개사 전부 같으므로 사람이 절과 낱말을 직접 이어 붙일 수
있다. 사용자가 제안한 방향이고 아직 안 만들었다.

### 확정하지 않은 값

```
RRF 가중치    1:1     사례 9개에서는 2:1 이 나았는데 37개로 늘리니 1:1 이 됐다
PATH_MIN      15.0    경로를 짚을 확신의 문턱
PATH_BOOST    20      짚은 경로를 몇 위까지 당길지
```

가중치는 8위내를 우선해서 골랐다. 생성 모델에 조각 여럿을 넣으므로
1위 적중보다 넓게 담는 쪽이 낫다고 봤다. 1위만 보면 1:5 가 낫다 (18/37).

한두 건에 순위가 뒤집히는 규모다. 사례가 늘거나 조건이 바뀌면 다시 잰다.
