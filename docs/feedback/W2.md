# W2 — 기준 계층

`company` 70행 · `document` 4,204행 적재.

작업 자체는 판단이 거의 없었다. 주최측이 제공한 `universe.csv`와 `manifest.jsonl`을 옮기는 일이라 추출도 파싱도 없다. 그럼에도 두 건이 걸렸다.

---

## 1. `report_nm` 형태가 세 가지였다

무엇을 했나
주요사항보고서의 세부 유형을 뽑기 위해 `report_nm`에서 괄호 안 문자열을 추출했다. `doc_subtype`이 major 598건 전부 결측이라 유형 정보가 여기밖에 없다.

정규식은 `[기재정정]` 접두를 제거하고 `주요사항보고서\((.+)\)`를 찾는 형태였다.

무엇이 문제였나
598건 중 597건만 추출됐다. 1건이 빠졌다.

어떻게 알았나
검증 스크립트. `major_kind`가 전건에서 추출되는지 확인하는 항목을 넣어두었고 거기서 걸렸다.

한 건이라 그냥 넘어갈 수도 있었다. 그러나 D1에서 28종을 분류할 때 누락되면 그 문서가 자금조달 조회에서 빠진다.

어떻게 고쳤나
실패 건을 열어보니 `report_nm`이 `'유상증자결정'`이었다. 래퍼가 없었다.

전수를 다시 세니 형태가 셋이었다.

```
592건  주요사항보고서(전환사채권발행결정)
  5건  [첨부추가]주요사항보고서(유상증자결정)     대체 수집분
  1건  유상증자결정                               래퍼 없이 유형명만
```

`[기재정정]`만 벗기던 것을 앞의 대괄호 태그 전체를 벗기도록 일반화하고, 래퍼가 있으면 괄호 안을 없으면 전체를 쓰도록 바꿨다. 598/598이 됐다.

무엇이 남았나
없다.

## 2. 외래키 삭제 순서

무엇을 했나
재실행 시 기존 데이터를 지우려고 각 적재 함수 안에서 `DELETE`를 했다.

무엇이 문제였나
`document`가 `company`를 참조하는데 `company`를 먼저 지워 외래키 제약에 걸렸다.

어떻게 알았나
두 번째 실행에서 예외로 터졌다. 첫 실행은 빈 테이블이라 통과했다.

어떻게 고쳤나
삭제를 별도 함수로 빼고 참조 역순으로 정리하도록 바꿨다.

무엇이 남았나
없다. 다만 이후 계층에서도 같은 패턴이 나올 수 있으니 삭제는 항상 역순으로 둔다.

---

## 3. 별칭 테이블을 만들려다 접었다

무엇을 했나
기업 지칭이 여럿이라 별칭 테이블을 만들 계획이었다. 포스코·하이닉스·삼바 같은 시장 은어를 사용자가 직접 정리해 주는 방식이었다.

무엇이 문제였나
불필요한 작업이었다.

어떻게 알았나
사용자 지적. "평가 규칙이 외부 데이터 추가를 금지하므로 평가 질의도 제공 데이터 안의 이름을 쓸 가능성이 높다"는 논거였다.

확인해 보니 `universe.csv`에 이미 세 가지 지칭이 들어 있었다.

```
corp_name     현대자동차       DART 공식 법인명
listed_name   현대차           거래소 통용 종목명
sector        자동차·모빌리티   "2차전지 기업 A와 B" 같은 지칭
```

어떻게 고쳤나
별칭 테이블을 만들지 않고 세 컬럼에 인덱스를 걸었다. 수작업이 사라졌다.

무엇이 남았나
없다. 다만 평가 질의가 실제로 시장 은어를 쓸 경우 못 찾는다. 그때는 행을 추가하면 되고, 발견은 demo test에서 특정 기업을 못 찾는 것으로 드러난다.

## 검증이 잡은 것과 사람이 잡은 것

| 항목 | 발견 경로 |
|---|---|
| `report_nm` 3종 | 검증 스크립트 |
| 외래키 삭제 순서 | 실행 오류 |
| 별칭 불필요 | 사용자 지적 |

세 번째는 검증으로 잡을 수 없는 종류다. "이 작업이 필요한가"는 코드가 판단하지 못한다.

## W3에 가져갈 것

검증을 조회 형태로 짜면 실수가 잡힌다. 행 수만 세는 검증이었다면 `report_nm` 1건은 그냥 통과했을 것이다.

`verify_base.py`에 넣은 항목 중 값을 한 것들이다.

```
4  실제 질의 형태로 조회   현대차 → 현대자동차, 2차전지 → 3개사
6  DATASET.md 실측값과 대조
7  파생 컬럼이 전건에서 추출됐는가
8  결측을 정상과 비정상으로 구분
```

8번이 특히 중요하다. `doc_subtype` 598건 결측과 `base_year` 3,150건 결측은 정상인데, 이걸 오류로 잡으면 존재하지 않는 문제를 쫓게 된다.
