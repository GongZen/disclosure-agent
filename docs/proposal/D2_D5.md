# D2. 설비투자의 의미

## 질문

"설비투자"를 물었을 때 어디를 봐야 하는가.

## 왜 정해야 하는가

과제 자료의 참고 질의 3번이 "2차전지 기업 A와 B 중 2025년 설비투자 규모가 더 큰 기업은 어디인가"이다. 평가에 나올 가능성이 높은 항목인데, 코퍼스에서 설비투자를 확인할 수 있는 자리가 셋이고 값이 서로 다르다.

## 관측된 사실

설비투자 정보가 나오는 자리는 최소 셋이다.

| 경로 | 위치 | 성격 | 건수·범위 |
|---|---|---|---|
| A | 거래소공시 `신규시설투자등` | 이사회 결의 단위. 금액·기간 명시 | 43건 |
| B | 정기공시 II-3 원재료 및 생산설비 | 기중 설비 증감 현황 | 비금융만. 금융 8개사는 해당 항목 없음 |
| C | 연결현금흐름표 유형자산 취득 | 실제 집행액 | 전 기업 |

세 값은 일치하지 않는다. 결의액과 집행액이 다르고 기간 구분도 다르다.

용어 분포 측정에서도 갈린다. 비금융 2025 사업보고서 61건 전수 기준으로 "설비"라는 단어가 II장에 100%, III장에 67%, IV장에 48%, I장에 66% 나온다. 한 곳에 몰려 있지 않다.

실제 사례로 SK하이닉스 2024년을 보면 경로 A에서 2건이 잡힌다.

```
청주 M15X 건설      5,296,200,000,000원   자기자본대비  9.90%
용인 Fab 건설       9,411,500,000,000원   자기자본대비 17.59%
합계               14,707,700,000,000원
```

같은 기간의 경로 C(현금흐름표 유형자산 취득)는 이 값과 다르다. 결의 시점과 집행 시점이 어긋나기 때문이다.

## 선택지

| 안 | 범위 | 장점 | 단점 |
|---|---|---|---|
| 1 | 경로 A만 | 값이 확정적이고 근거 공시가 명확. `event_contract`에 이미 적재됨 | 거래소공시 기준 금액 미만 투자가 빠짐. 금융업은 43건 중 해당 없음 |
| 2 | A + B | 사업보고서 설비 현황까지 포괄 | B는 비금융만 있고 서식이 기업마다 달라 추출 난도가 높음 |
| 3 | A + C | 결의액과 집행액을 함께 제시 | 두 값이 달라 어느 쪽이 답인지 이용자가 혼란 |

## 파트너 의견

1안을 기본으로 하되 답변에 범위를 명시하는 방식을 제안한다.

근거는 세 가지다.

첫째, 경로 A는 W4에서 이미 `event_contract`에 적재되어 있다. `event_type = 'investment'` 43건이고 `amount_krw`·`base_amount`·`ratio_stated`가 다 들어 있다. 추가 작업 없이 SQL로 답이 나온다.

둘째, 경로 B는 서식이 기업마다 다르다. III-8 구조 분석에서 확인했듯 정기공시의 하위 소제목은 표기 변형이 심하고 표 구조도 통일되어 있지 않다. 남은 기간에 안정적으로 추출하기 어렵다.

셋째, 경로 C는 성격이 다른 값이다. 유형자산 취득액은 설비 외 자산도 포함하고 결의 시점과 무관하게 집행 시점으로 잡힌다. 같은 질문의 답으로 나란히 놓으면 오히려 부정확해진다.

다만 1안만으로 답하면 지표 2번(근거 완전성)에서 손실이 있을 수 있으므로, 답변에 아래 문장을 붙이는 것을 함께 제안한다.

```
[유의] 이 답변은 거래소공시 '신규시설투자등' 유형에 한정한 결과입니다.
       실제 집행된 설비투자액은 연결현금흐름표의 유형자산 취득액과,
       기중 설비 증감 현황은 사업보고서 II-3 원재료 및 생산설비 항목과
       다를 수 있습니다.
```

## 합의가 필요한 지점

```
1  1안으로 갈 것인가, 3안으로 두 값을 병기할 것인가
2  1안이면 위 [유의] 문구를 표준 문안으로 고정할 것인가
3  금융 8개사에 신규시설투자 공시가 없을 때 no_document 로 답할 것인가
   (D7 네 갈래 중 어디에 해당하는지)
```

# D5. 기간 해석

## 질문

질의의 "2025년"이 무엇을 가리키는가.

## 왜 정해야 하는가

S1 질의 해석과 S3 문서 선별이 이 정의 위에서 동작한다. 기간 해석이 틀리면 대상 문서가 통째로 어긋난다.

## 관측된 사실

### 정기공시와 수시공시가 다르다

`document` 테이블 4,204행 기준이다.

| 구분 | 건수 | `base_year` |
|---|---|---|
| 정기공시 | 1,054 | 100% 존재 |
| 수시공시 (거래소·주요사항·지분) | 3,150 | 전부 NULL |

정기공시는 보고 기준기가 있어서 회계연도로 바로 걸린다. 수시공시는 없어서 `rcept_dt`로만 필터할 수 있다.

### 수시공시는 날짜가 여러 개다

삼성전자 2025년 7월 계약 공시 하나에 날짜가 셋이다.

```
계약 시작일      2025-07-24
계약(수주)일자   2025-07-26
접수일          2025-07-28
```

셋 다 다르다. "2025년 7월에 체결한 계약"이라는 질의가 어느 날짜를 가리키는지 정해야 한다.

### 미래를 공시하는 경우가 있다

Ford 계약 해지 건이 대표적이다.

```
계약기간   2027-01-01 ~ 2032-12-31
해지일자   2025-12-17
```

계약 기간이 아직 시작도 안 한 상태에서 해지됐다. 이 건을 "2025년 계약"으로 볼지 "2027년 계약"으로 볼지가 갈린다.

한화에어로스페이스 유상증자도 같은 구조다.

```
이사회결의일   2025-03-20
납입일         2025-06-12  (원본)  →  2025-07-09  (최종 정정)
```

결의와 실제 자금 유입 시점이 4개월 차이나고, 정정으로 또 밀렸다.

### 스키마에 이미 날짜가 여러 개 있다

`docs/SCHEMA.md` 확인 결과다.

| 테이블 | 날짜 컬럼 |
|---|---|
| `document` | `rcept_dt` 접수일 · `base_year` `base_month` 보고 기준기 |
| `event_contract` | `start_date` · `end_date` · `signed_at` |
| `event_major` | `decided_at` 이사회결의일 |

`event_contract`가 이미 세 날짜를 나눠 담고 있다. 아래 제안이 스키마 변경 없이 성립한다는 뜻이다.

## 파트너 제안

세 갈래로 나눈다.

```
1  정기공시    보고 기준기 (base_year · base_month) 로 건다
              "2025년 매출액" → base_year = 2025 인 사업보고서

2  수시공시    접수일 (rcept_dt) 을 기본 필터로 쓴다
              "2025년에 공시한 계약" → rcept_dt LIKE '2025%'

3  실행 시점   기본 필터와 별개로 답변에 함께 제시한다
              계약이면 start_date · end_date
              유상증자면 납입일
              해지면 계약기간과 해지일자를 나란히
```

3번이 핵심이다. 공시는 앞으로 일어날 일을 알리는 문서인 경우가 많다. 공시 시점만 답하면 이용자가 실제로 언제 일어나는 일인지 알 수 없다.

Ford 건을 예로 들면 이렇게 답한다.

```
2025년 12월 17일 공시된 해지 건입니다.
해당 계약의 계약기간은 2027-01-01 ~ 2032-12-31로, 계약 개시 전에 해지되었습니다.
```

공시일과 실행 시점을 둘 다 말하면 "2025년 계약인가 2027년 계약인가"라는 모호함이 사라진다. 질의가 어느 쪽을 의도했든 답이 성립한다.

## 이 제안의 효과

평가지 문항 22(LG에너지솔루션 실적 변화)에서 확인된 실패를 막는다. 그 문항에서 Ford 계약 해지를 실적 감소 근거로 제시했다가 계약이 아직 개시되지 않았다는 사실이 드러나 답변 전체를 다시 썼다.

기본 필터가 접수일이더라도 실행 시점을 함께 꺼내 두면, 코드가 계약기간과 회계기간의 교집합을 계산해 무관한 근거를 걸러낼 수 있다.

```
이벤트 공시를 실적 변화의 근거로 제시하기 전에
계약기간과 대상 회계기간의 교집합을 계산한다.
교집합이 없으면 근거에서 제외하거나 "해당 기간 매출에 반영되지 않음"을 표기한다.
```

## 합의가 필요한 지점

```
1  수시공시 기본 필터를 접수일로 할 것인가
   대안 — 사건 발생일(signed_at) 을 기본으로 하고 접수일을 보조로

2  실행 시점을 답변에 항상 제시할 것인가, 질의가 기간을 물었을 때만 할 것인가

3  주요사항보고서의 실행 시점(납입일 등)을 어디서 꺼낼 것인가
   event_major 에는 decided_at 만 있고 납입일은 major_item 에 있을 것으로 보임
   자주 쓰는 축이면 event_major 에 컬럼 추가를 검토

4  정기공시와 수시공시를 함께 묻는 질의의 처리
   "2025년 삼성전자 관련 공시 전부" 같은 경우 두 기준이 섞인다
```

# 부록. 시장명 한글 표기

D2·D5 와 별개 사안이지만 같은 시점에 확인되어 함께 올린다.

## 질문

`market` 컬럼을 한글로 물었을 때 찾을 것인가.

## 왜 정해야 하는가

S2 대상 확정을 구현하며 실측한 결과다.

```
"KOSDAQ"  →  9개사 확정
"코스닥"   →  out_of_scope
```

`company.market` 의 값이 `KOSPI` · `KOSDAQ` 두 개뿐이고 영문 표기다. 질의가 한글로
오면 못 찾는다.

## 관측된 사실

`docs/SCHEMA.md` 기준 계층 절이 별칭 테이블을 두지 않기로 정했다.

```
별칭 테이블은 두지 않는다. 포스코·하이닉스 같은 시장 은어는 제공 데이터
어디에도 없고, 평가 규칙이 외부 데이터 추가를 금지하므로 평가 질의도
제공 데이터 안의 이름을 쓸 가능성이 높다.
```

이 결정에 따라 아래는 지금도 찾지 못하며, 설계대로 동작하는 것이다.

| 질의 | DB 값 | 성격 |
|---|---|---|
| 포스코 | POSCO홀딩스 | 시장 은어. SCHEMA 가 예시로 명시 |
| 네이버 | NAVER | 시장 은어 |
| 하이닉스 | SK하이닉스 | 시장 은어 |

`코스닥` 은 성격이 다르다. 회사의 별명이 아니라 시장 이름의 한글 표기다.
`KOSDAQ` 과 `코스닥` 은 같은 대상을 가리키는 같은 이름이고, 표기 문자만 다르다.

그리고 자체 평가 문항에서 실제로 한글로 나왔다.

```
자체제작 3  "코스닥 기업들 중에서 90일 이상 연체된 채권의 비율이 …"
```

## 선택지

| 안 | 내용 | 결과 |
|---|---|---|
| 1 | 지금대로 둔다 | SCHEMA 결정 그대로. 평가 질의가 영문을 쓴다는 가정에 의존 |
| 2 | 시장 두 값만 한글 대응 | KOSPI↔코스피 · KOSDAQ↔코스닥 두 줄. 기업명은 손대지 않음 |
| 3 | 별칭 테이블 도입 | SCHEMA 결정을 뒤집음. 기업 은어까지 열림 |

## 파트너 의견

2안을 제안한다.

근거는 셋이다.

첫째, 두 줄이라 별칭 테이블이 아니다. `market` 컬럼의 값이 둘뿐이므로 대응 관계도
둘이다. SCHEMA 가 우려한 "외부 데이터 추가"에 해당하지 않는다. 코퍼스 안에 있는
값의 한글 표기일 뿐이다.

둘째, 기업명 은어와 성질이 다르다. 포스코·하이닉스는 회사가 쓰지 않는 별명이라
어디까지 인정할지 경계가 없다. 시장명은 KOSPI·KOSDAQ 둘로 닫혀 있다.

셋째, 한글 질의가 실제로 나온다. 자체 평가 문항이 그 예이고, 국내 공시를 다루는
서비스에 "코스닥 기업"이라는 표현이 오지 않는다고 보기 어렵다.

3안은 반대한다. 기업명 은어를 열면 어디서 멈출지 정할 근거가 없고, SCHEMA 가
이미 그 이유로 닫아둔 결정이다.

## 합의가 필요한 지점

```
1  2안으로 갈 것인가
2  간다면 대응 관계를 어디에 둘 것인가
     src/match.py 안의 상수     — W7 소유. 지금 방식
     company 테이블 컬럼 추가    — W2 소유. 상대방 작업
3  KOSPI 를 "유가증권시장" 으로 부르는 경우도 넣을 것인가
```

2번이 실질적인 결정이다. 지금은 S2 구현 안에 두는 것을 전제했으나, 기준 계층에
속하는 정보로 본다면 `company` 쪽이 맞다.
