# 제안 — 합의 전 문서

아직 합의되지 않은 제안을 둔다. 확정 문서와 섞이지 않게 분리한 것이다.

다른 문서와의 역할 구분이다.

| 문서 | 담는 것 | 상태 |
|---|---|---|
| `docs/PLAN.md` `PIPELINE.md` `GLOSSARY.md` `SCHEMA.md` | 합의된 기준 | 확정 |
| `docs/proposal/*.md` | 한쪽이 제시한 안 | 미확정 |
| `docs/feedback/W*.md` | 작업 중 무엇이 왜 틀렸나 | 기록 |
| `DECISIONS.md` | 되돌리기 어려운 선택과 근거 | 확정 |

`docs/` 바로 아래는 라우팅 표(`CLAUDE.md`)에 등재된 기준 문서만 둔다. 제안은 등재 대상이 아니므로 이 폴더로 내린다.

---

## 다루는 방식

```
1  제안자가 이 폴더에 파일을 만들고 브랜치로 올린다
2  PR 코멘트로 논의한다
3  합의되면 해당 정의를 GLOSSARY.md 또는 SCHEMA.md 에 반영한다
4  반영이 끝나면 이 폴더의 파일은 지운다
```

4번이 중요하다. 제안이 반영된 뒤에도 남아 있으면 어느 쪽이 최신인지 알 수 없게 된다.

---

## 형식

각 제안에 아래를 담는다.

| 항목 | 내용 |
|---|---|
| 질문 | 무엇을 정해야 하는가 |
| 왜 정해야 하는가 | 이것이 안 정해지면 무엇이 막히는가 |
| 관측된 사실 | 코퍼스 실측. 추정과 구분해 적는다 |
| 선택지 | 가능한 안과 각각의 결과 |
| 제안 | 무엇을 고르고 왜 그것인가. 다른 쪽은 왜 아닌가 |
| 합의가 필요한 지점 | 상대방이 답해야 할 것 |
