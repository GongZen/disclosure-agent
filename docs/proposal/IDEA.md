# 정성평가 대응 아이디어 정리

공시 Agent 의 결과 활용성과 창의성을 높이기 위한 아이디어를 모았다.
합의된 것이 아니라 한쪽이 제시한 안이다.

1절 한눈에 보기만 읽어도 전체가 파악되게 썼다. 관심 가는 항목만 아래 상세로 가면 된다.

작성 2026-08-28 · 갱신 2026-08-29 · 마감 09-06

# 0. 평가 기준

세 축으로 본다.

```
실현 가능성   9일 안에 되는가. 남의 작업을 기다려야 하는가
유용성        쓰는 사람에게 실제로 값이 있는가
평가 연결     예선 정량 · 예선 정성 · 결선 중 어디에 점수가 되는가
```

## 0-1. 알고 있어야 할 제약

### 예선 정량은 JSON 네 필드가 전부다

```
question_id · question · retrieved_context · think_trace · answer
```

파일 첨부도 화면도 없다. 엑셀·PDF·버튼은 예선 정량평가에 0점 기여다.
`answer` 가 문자열이므로 표는 들어간다. 이 선이 비용과 효과를 가른다.

### 정성평가 항목은 다섯이다

```
문제정의
기술완성도 · 성능
창의성 · 확장성
답변의 정확성 · 완결성
협업 활용성 · 리스크 관리
```

무엇을 보고 이 항목들을 채점하는지는 과제 자료에 없다. 제출물 3종 중
기술제안서가 재료일 가능성이 높다고 보지만 확정된 사실이 아니다.

### 결선은 라이브 시연 중심이다

본선 6팀 대상. 화면이 필요한 아이디어는 여기서만 값이 난다.
결선에 못 가면 회수되지 않는 투자다.

### 절대 제약

```
HyperCLOVA X 외 생성 모델 금지
제공 코퍼스 외 데이터 금지
외부 공시 API 실시간 호출 금지
공시에 근거 없는 미래 예측·투자 의견 금지
```

마지막 줄이 6절 민감도 아이디어를 직접 제약한다.

# 2. 답변 안에서 되는 것

`answer` 문자열 안에서 끝나므로 예선 정량과 정성 양쪽에 걸린다.
넷 다 S8·S9·S11 을 만들 때 같이 넣는 것이라 추가 비용이 거의 없다.

## 2-1. 비교 결과를 표로 출력

3년 추이나 여러 기업 비교를 표로 정리해 답변에 담는다.

| 항목 | 내용 |
|---|---|
| 실현 | 지금 됨. `[근거]` 블록의 표현 형식을 정하는 일 |
| 유용 | 읽는 사람이 바로 씀. 문서 내보내기의 저비용 대체재 |
| 평가 | 지표 3 요구사항 충족 · 답변 완결성 |

주의가 둘이다.

첫째, 표는 `[결론]` 을 대체하지 않는다. "삼성전자가 더 크다" 라는 문장 없이
숫자만 늘어놓으면 비교 질의에 답하지 않은 것이 된다.

둘째, 평가자가 마크다운으로 렌더링해 보는지 평문으로 보는지 알 수 없다.
파이프 표는 렌더링 안 되면 읽기 나쁘므로 공백 정렬이 안전하다. 평가지 답변이
이미 공백 정렬을 쓰고 있다.

3년 추이에 그래프는 필요 없다고 본다. 점이 셋이라 선을 그려도 정보가 늘지 않고,
숫자를 정확히 보여주는 쪽이 지표 1 정확성에 직결된다.

## 2-2. 값의 출처 구분 — 공시 기재값인가 우리 계산값인가

| 항목 | 내용 |
|---|---|
| 실현 | 지금 됨. S8 에 플래그 하나 |
| 유용 | 원문 숫자와 우리 숫자를 섞지 않는다 |
| 평가 | 지표 4 근거 기반 · 리스크 관리 |

근거가 되는 실측이 있다. 계약 공시에 `매출액대비(%)` 가 1,080건 이미 들어 있고,
유상증자 공시에는 `기준매수가격[(①+②+③)/3]` 처럼 계산식까지 항목 이름에 박혀 있다.
이미 있는 값을 우리가 다시 계산하면 반올림 자리나 분모 기준 차이로 어긋날 수 있다.

`PIPELINE.md` S8 의 남기는 것이 "계산식과 중간값" 이므로, 인용한 경우 그 자리에
"공시 기재값" 이라고 남기면 구분이 된다.

| 유용 | 같은 항목이 시점마다 다른 값을 갖는 문제를 막는다 |

자체제작 1 에서 실제로 겪은 문제다. 이재용 회장의 삼성전자 지분율이 한 보고서

# 3. 근거의 주소와 링크

## 3-1. 근거 주소를 장·절까지 정밀화

답변에 "III. 재무에 관한 사항 > 2. 연결재무제표 > 연결 손익계산서" 처럼
어느 자리에서 왔는지를 적는다.

실측으로 확인한 것이 있다. 사업보고서 XML 의 `TITLE` 태그에 주소 역할을 하는
속성이 있고, 기업이 달라도 같은 코드다.

```
<TITLE ATOC="Y" AASSOCNOTE="D-0-1-3-0" ATOCID="6">3. 자본금 변동사항</TITLE>

삼성전자 · SK하이닉스 · LG에너지솔루션   모두 코드 51종
D-0-1-3-0  →  3. 자본금 변동사항        세 회사 동일
```

`(접수번호, AASSOCNOTE)` 두 개로 주소가 된다. 기업마다 다시 만들 필요가 없다.

| 항목 | 내용 |
|---|---|
| 실현 | 사업보고서 장·절은 지금 됨. 코드↔제목 사전 한 번 |
| 유용 | 근거를 눈으로 찾아갈 수 있다 |
| 평가 | 지표 2 근거 완전성 · 답변 완결성 |

## 3-2. 주석 항목 단위 주소 — W6 이전에 정해야 한다

주석 개별 항목에는 태그 주소가 없다. 실측하면 주석 파일 전체가
`AASSOCNOTE="D-0-1-0-0"` 하나로 묶여 있고, 그 안의 `1. 현금및현금성자산`
`6. 재고자산` 같은 항목은 본문 텍스트로만 존재한다.

즉 "연결주석 15번" 단위로 짚으려면 청킹할 때 제목을 파싱해 따로 기록해야 한다.

이게 시급하다. `PLAN.md` W6 이 "청킹 단위는 뒤집기 어렵다. 바꾸면 전체를 다시
임베딩해야 한다" 고 적어놨다. W6 이 미착수인 지금이 유일하게 싼 시점이고,
W6 은 파트너 작업이므로 착수 전에 전달해야 한다.

| 항목 | 내용 |
|---|---|
| 실현 | W6 에서 같이 하면 낮음. 나중에 하면 재임베딩 |
| 유용 | 주석은 정성 질의의 핵심 근거다 |
| 평가 | 지표 2 · 창의성 |

## 3-3. 클릭 가능한 링크

답변의 근거를 누르면 원문의 그 자리로 이동한다.

| 항목 | 내용 |
|---|---|
| 실현 | 중간~큼. XML→HTML 변환과 라우트가 필요 |
| 유용 | 활용성이 크게 오른다 |
| 평가 | 예선 정량 0. 협업 활용성 · 기술완성도 · 결선 |
| 시점 | W9 배포가 안정된 뒤 |

링크가 가리킬 곳이 두 갈래다.

```
우리 서버에서 원문을 띄운다      코퍼스 안에서 끝난다. 안전
DART 공시뷰어로 보낸다          접수번호로 URL 이 만들어지나 코퍼스 밖으로 나간다
```

뒤쪽은 우리가 API 를 호출하는 건 아니지만 절대 금지 2·3 의 취지에 걸리는지
파트너와 확인이 필요하다.

주소만 정밀하게 남겨두면 나중에 링크를 거는 건 짧은 작업이다. 반대로 주소를
안 남기고 나중에 링크만 붙이려 하면 원문을 다시 훑어야 한다.

| 형식 | 실현 | 비고 |

| PDF | 큼 | 생성 라이브러리 추가 + 한글 폰트 임베드 |

| 항목 | 내용 |
|---|---|
| 유용 | 실무자가 받아서 바로 가공한다 |
| 평가 | 예선 정량 0. 협업 활용성 · 창의성 · 결선 |
| 시점 | W9 이후. 시간이 없으면 제안서에 설계로만 |

엑셀과 PDF 사이 비용 차이가 크다. 하나만 한다면 엑셀이다.

기술제안서가 자유 양식이고 "기대효과 · 확장성" 항목이 있으므로, 구현하지 않은
확장 방향을 설계로 제시하는 것도 항목상 허용된다.

# 6. 민감도 연결 — 공시가 제시한 가정을 재무 영향으로 환산

## 6-1. 아이디어

공시에는 판단의 근거나 가정이 적혀 있는 항목이 있다. 재무위험, 손상검사 가정,
확정급여채무의 보험수리적 가정 같은 것들이다. 이 가정이 변하면 자산·부채와
재무 상황이 얼마나 달라지는지를 계산해 보여준다.

## 6-2. 관측된 사실

2025 사업보고서 12건을 표본으로 확인했다. 12건 전부에 "민감도" 가 나온다.

```
알테오젠 22 · 기아 15 · 케이티 53 · LG생활건강 57 · LG유플러스 45 · NAVER 75
두산퓨얼셀 24 · 셀트리온 25 · HMM 64 · 한전기술 21 · 삼성전기 58 · NC 54
```

그런데 실제 표를 열어보면 이미 계산되어 있다. 기아 사업보고서 주석의
보험수리적가정 민감도분석이다.

```
                                        할인율      미래임금상승률
발생가능한 증가율                          0.01        0.01
증가로 인한 확정급여부채의 증가(감소)      (210,219)    240,972
발생가능한 감소율                          0.01        0.01
감소로 인한 확정급여채무의 증가(감소)       237,941    (216,532)
                                        (단위 : 백만원)
```

즉 "할인율 1%p 오르면 부채 2,102억 감소" 라는 계수를 회사가 이미 공시했다.

## 6-3. 그래서 우리 몫이 어디인가

이 사실이 아이디어의 성격을 바꾼다. 셋으로 갈린다.

| 우리가 하는 일 | 근거 | 판정 |
|---|---|---|
| 공시된 민감도 계수를 찾아 답변에 연결 | 원문 그대로 | 안전. 값어치는 여기 있다 |
| 계수를 규모 대비 비율로 환산 | 두 공시 값의 나눗셈 | 안전. 실질적 기여 |
| 공시 범위 밖으로 외삽 | 없음 | 위험. 하지 않는 것이 맞다 |

두 번째가 실제 기여다. "할인율 1%p 변동 시 확정급여부채 2,379억 변동" 이라는
숫자만으로는 크기를 가늠하기 어렵다. 같은 보고서의 자기자본이나 부채총계로
나누면 "자기자본의 X%" 가 되고, 그건 두 공시 값의 나눗셈이라 근거가 있다.

세 번째는 하면 안 된다. 공시가 "합리적인 범위 내에서의 발생가능한" 이라고
한정해 두었다. 2%p 라고 두 배로 늘리는 것은 선형을 가정하는 것이고 근거가 없다.
여러 변수를 동시에 움직이는 것도 상호작용을 무시하는 것이라 마찬가지다.
`CLAUDE.md` 절대 금지 4 의 "공시에 근거 없는 미래 예측" 에 걸린다.

## 6-4. 평가

| 항목 | 내용 |
|---|---|
| 실현 | 민감도 표는 주석에 있다. W6 본문 계층이 있어야 찾을 수 있다 |
| 유용 | 높다. 숫자에 크기 감각을 붙여준다 |
| 평가 | 창의성 · 답변 완결성 · 리스크 관리 |
| 위험 | 외삽으로 새기 쉽다. 경계를 코드로 막아야 한다 |

W6 에 걸려 있어 지금 착수할 수 없다. 다만 어떤 표를 찾아야 하는지는 지금
정할 수 있고, 그건 3-2 의 주석 항목 주소와 같은 작업이다.

## 6-5. 비교 대상

같은 자리에 놓고 볼 만한 대안이 있다.

| 방향 | 차이 |
|---|---|
| 민감도 계수 연결 + 규모 환산 | 공시 안에서 끝난다. 근거가 명확하다 |
| 우리가 시나리오를 만들어 계산 | 표현력은 크나 근거가 없다. 지표 4 위반 |
| 민감도가 있다는 사실만 안내 | 안전하나 값어치가 낮다 |

첫째가 유일하게 규칙 안에서 값을 내는 방향으로 보인다.

# 7. 관련 정보 안내와 추가 공시 참조

두 아이디어로 나왔지만 밑바닥이 같다. 하나는 무엇을 더 볼 수 있는지 알려주는
표현이고, 다른 하나는 그 목록을 만드는 데이터다. 같이 만들어야 한다.

## 7-1. 관련 항목을 안내한다

CB 를 물으면 "투자와 관련해 다른 항목도 있는데 조사해드릴까요" 처럼 덧붙인다.

### 규칙과 부딪히는 지점

`PLAN.md` W8 과 `PIPELINE.md` S10 이 되묻기를 금지한다.

```
되묻는 문장은 두지 않는다. 평가는 GET 요청 한 번으로 끝나므로
되물으면 그 질의의 답이 없고, 지표 1과 3에서 얻을 점수가 사라진다.
```

그런데 대회 지표 7 원문에는 역질문이 인정 수단으로 적혀 있다.

```
보유 데이터로 답변할 수 없는 질의를 식별하고, 무리한 답변 대신
한계 고지 또는 필요한 정보를 역질문으로 대응하는가
```

둘이 충돌하는 것처럼 보이지만 적용 대상이 다르다. 지표 7 의 역질문은 답할 수
없는 질의에 대한 대응이고, 팀 규칙은 그 경우에도 한계 고지 쪽을 고른 것이다.
GET 한 번으로 끝나므로 되물으면 그 질의는 무득점이라는 계산이다.

### 그래서 어떻게 하면 되는가

이 아이디어는 답할 수 없는 질의에 대한 되묻기가 아니다. 답을 다 한 뒤에 덧붙이는
안내다. 그 자리는 이미 규칙 안에 있다. `PLAN.md` W8 답변 형식 4단계의 4번이다.

```
1. 답할 수 있는 만큼 답한다
2. 어떤 기준으로 골랐는지 밝힌다
3. 답하지 못한 부분은 범위 밖·미공시·추출 실패로 구분해 적는다
4. 다른 관점이나 후보를 안내한다      ← 여기
```

따라서 문장을 질문형이 아니라 서술형으로 쓰면 규칙 안에서 그대로 된다.

```
안 됨   전환사채 외에 유상증자 내역도 조사해드릴까요?
됨      같은 날 유상증자결정도 함께 공시되어 있습니다. 접수번호 …
```

앞은 평가자가 답해야 다음이 있고, 뒤는 그 자체로 정보다. 내용은 같고 점수는 다르다.

| 항목 | 내용 |
|---|---|
| 실현 | 낮음. 문장 형식 규칙 + 7-2 의 목록이 있으면 됨 |
| 유용 | 높음. 사용자가 무엇을 더 물어야 할지 모를 때 길을 열어준다 |
| 평가 | 지표 3 요구사항 충족 · 지표 7 · 협업 활용성 |
| 위험 | 질문형으로 쓰면 지표 1·3 을 잃는다. 형식을 코드로 강제해야 한다 |

## 7-2. 관련 가능성이 높은 구역에 추가 공시 참조를 건다

### 지금 있는 것

`doc_relation` 테이블은 두 종류뿐이다. 주제 연관은 들어 있지 않다.

```
correction    1,004건    정정본과 원본
termination      20건    해지와 원계약
```

즉 새로 만들어야 한다. 다만 재료는 이미 있고 값이 싸다.

### 쓸 수 있는 신호 넷

실측으로 확인한 것들이다 (2026-08-28).

```
1  같은 기업 · 같은 날 공시            묶음 187개. 3건 이상 15개. doc_group 이 섞인 묶음 50개
2  같은 사건의 다른 서식              디앤디파마텍 2025-06-11
                                    전환사채권발행결정 · 자본으로인정되는채무증권발행결정 ·
                                    타법인주식및출자증권양수결정 세 건이 같은 날
3  사업보고서 섹션 코드                AASSOCNOTE 51종. 기업이 달라도 동일
4  사건 이후의 후속 공시               CB 발행 이후 지분공시
                                    에코프로비엠 65건 · 에스엠 16건 · 하이브 13건
```

1번이 가장 싸다. `document` 테이블의 `corp_code` 와 `rcept_dt` 만으로 나온다.
새 데이터도, 새 추출도 필요 없다.

에스엠 2023-02-07 에 전환사채권발행결정과 유상증자결정이 같은 날 나온 것이
그 예다. CB 를 물은 사용자에게 유상증자를 안내할 근거가 "같은 날 공시" 하나로
성립한다.

### 무엇을 안내할 것인가

주제별로 볼 자리를 미리 정해둘 수 있다. CB 를 예로 들면 이렇다.

```
주요사항보고서   전환사채권발행결정 · 자본으로인정되는채무증권발행결정
사업보고서       III-7 증권의 발행을 통한 자금조달에 관한 사항
                I-3  자본금 변동사항
지분공시         발행 이후의 대량보유상황보고서 (전환에 따른 지분 변동)
```

셋째 줄까지는 `AASSOCNOTE` 코드로 주소가 나오고, 넷째 줄은 날짜 비교로 나온다.

| 항목 | 내용 |
|---|---|
| 실현 | 신호 1·2·4 는 지금 됨. 신호 3 은 섹션 사전 한 번 |
| 유용 | 높음. 공시는 한 사건이 여러 서식으로 흩어지는 것이 기본이다 |
| 평가 | 지표 2 근거 완전성 · 창의성 · 협업 활용성 |
| 위험 | 관련 없는 것을 관련 있다고 붙이면 지표 4·6 에 해가 된다 |

### 위험을 다루는 방법

연관의 근거를 함께 밝힌다. "관련 있습니다" 가 아니라 "같은 날 공시되었습니다"
"같은 사업보고서의 다른 절입니다" 라고 적는다. 근거를 못 대는 연관은 붙이지 않는다.

특히 신호 4 는 조심해야 한다. CB 발행 뒤에 지분공시가 있다는 사실이 그 지분 변동이
전환 때문이라는 뜻은 아니다. 시간 순서일 뿐 인과가 아니다. 평가지 문항 22 에서
이미 같은 실수를 했다. 계약 해지를 매출 감소의 원인으로 적었는데 계약기간이
시작되지도 않은 건이었다.

## 7-3. 둘을 합쳐서 보면

7-2 가 목록을 만들고 7-1 이 그것을 문장으로 낸다. 따로 만들 이유가 없다.

그리고 이 조합은 3-1 근거 주소와도 같은 재료를 쓴다. `AASSOCNOTE` 섹션 사전이
셋 모두에 들어간다. 하나 만들어 셋에 쓰는 셈이라 비용 대비 효과가 이 문서에서
가장 좋은 축에 든다.

# 8. 공시 용어 설명 덧붙이기

## 8-1. 아이디어

질의에 나온 공시 용어에 설명을 덧붙인다. CB 를 물으면 답변 아래에 전환사채가
무엇인지 한 줄 붙이는 식이다.

## 8-2. 절대 규칙에 걸리는가 — 걸리지 않는다

조문을 하나씩 대보면 이렇다.

| 조항 | 해당 여부 |
|---|---|
| 1. HyperCLOVA X 외 LLM 금지 | 무관 |
| 2. 제공 코퍼스 외 데이터 금지 | 해당 없음 |
| 3. 외부 공시 API 실시간 호출 금지 | 무관 |
| 4. 공시에 근거 없는 미래 예측·투자 의견 금지 | 해당 없음 |

2번이 막는 것은 뉴스·애널리스트 리포트·위키·웹 크롤링, 즉 실행 중에 외부에서
가져오는 자료다. 모델이 학습으로 이미 아는 용어의 뜻을 쓰는 것은 다른 층위다.
7-1 절에서 절 선택을 두고 정리한 것과 같은 논리다.

4번은 예측과 투자 의견을 막는다. 용어 정의는 둘 다 아니다.

## 8-3. 진짜 위험은 지표 4다

지표 4 근거 기반이 "Context 에 없는 내용을 사실처럼 생성하지 않았는가" 를 본다.
용어 정의는 `retrieved_context` 에 없다. 채점자가 hallucination 으로 볼 여지가 있다.

코퍼스에서 정의를 구할 수 있는지 재봤는데 안 된다 (2026-08-30).

```
있음   전환가액 165건 · 전환청구기간 69건 · 전환비율 33건 · 옵션 350건 · 조기상환 435건
없음   전환사채란 무엇이다 같은 정의성 서술
```

조건은 상세히 있는데 정의는 없다. 그래서 코퍼스에서 인용한다는 안전한 길이 막힌다.

## 8-4. 값어치도 따져볼 필요가 있다

정성평가가 기술·도메인 전문가 검토로 진행되므로 채점자는 CB 가 무엇인지 안다.
예선 정량에는 도움이 되지 않고, 오히려 지표 3 요구사항 충족에서 묻지 않은 내용으로
감점될 수 있다.

값은 실사용자와 협업 활용성 쪽에서 난다. 결선 시연에서도 쓸모가 있다.

## 8-5. 안전하게 만드는 방법

셋 중 하나 또는 조합이다.

```
가  정의 대신 그 공시의 조건을 풀어 쓴다
      전환가액 58,847원에 2026-06-20부터 주식으로 전환할 수 있습니다
      코퍼스 안이라 지표 4 에 걸리지 않는다

나  답변 본문과 분리하고 출처가 공시가 아님을 명시한다
      참고 표시를 붙이고 일반 정의이며 공시 기재가 아님을 적는다

다  분량을 한 줄로 제한한다
```

가 방식을 제안한다. 가장 안전하면서 정보량도 더 많다. 일반 정의보다 그 회사의
실제 조건이 쓰는 사람에게 유용하다.

나 방식은 정의가 꼭 필요할 때만 쓴다. 이때 표시를 분명히 해야 채점자가 답변 본문의
근거와 구분한다.

## 8-6. 7절과 같은 제약을 받는다

관련 항목 안내와 성격이 같다. 답을 다 한 뒤에 덧붙이는 정보이고, 길어지면 정작 물은
것이 묻힌다. 분량 제한과 위치 규칙을 함께 쓴다.

# 9. 스스로 반박해 둘 것

## 9-1. 정성평가가 무엇을 보는지 모른다

정성평가가 "기술·도메인 전문가의 검토" 로 진행된다고만 되어 있다. 제안서를
보는지, 코드를 보는지, 답변만 보는지 명시가 없다.

세 경우 모두에서 값이 나는 것은 1-1 이다. 답변 자체의 품질이기 때문이다.
1-3 은 제안서나 시연을 본다는 전제에서만 값이 난다. 이 불확실성이 우선순위를
1-1 쪽으로 미는 근거다.

## 9-2. 아이디어가 많은 것이 창의성인가

항목이 "창의성 · 확장성" 으로 묶여 있다. 확장성이 붙어 있다는 것은 지금 있는
기능의 개수보다 구조가 열려 있는지를 본다는 뜻일 수 있다. 그렇다면 기능을
늘리는 것보다, 근거를 주소로 남겨두어 나중에 화면이든 문서든 붙일 수 있게
해두는 쪽이 항목에 더 맞는다. 이건 해석이고 확정은 아니다.

## 9-3. 관련 정보 안내가 오히려 감점이 될 수 있는가

가능하다. 지표 3 은 질의에서 요구한 사항을 답했는지를 본다. 묻지 않은 것을
길게 붙이면 정작 물은 것이 묻힌다. 그리고 지표 4 는 Context 에 없는 내용을
사실처럼 만들지 않았는지를 본다. 연관을 단정하면 여기 걸린다.

그래서 두 가지를 지켜야 한다. 안내는 답 뒤에 짧게 두고, 연관의 근거를 반드시
함께 적는다. 분량은 문장 한둘 또는 목록 서너 줄을 넘기지 않는 것이 맞다고 본다.
