# 사업보고서 정보 연결 지도

질의가 들어왔을 때 사업보고서의 어느 자리를 봐야 하는지를 정하기 위한 실사 기록이다.
2025 사업보고서 전수를 재서 얻은 결과와, 그것을 검색 레이어에 어떻게 적용할지를 담았다.

본문 1~5절이 지금 필요한 부분이다. 부록은 그 근거가 된 측정 상세와 당장 쓰지 않는
구조 분석이다.

작성 2026-08-14 · 갱신 2026-08-30

# 0. 개괄

전체를 다 읽지 않아도 되게 각 절의 요지를 먼저 적는다.
본문 1~5절이 지금 필요한 부분이고 부록은 근거와 배경이다.

| 절 | 제목 | 요지 |
|---|---|---|
| 1 | 요약 | 질의를 목차에 잇는 일은 3층으로 갈린다. 1·2층은 원문 코드로 확정되고 3층만 검색이 필요하다 |
| 2 | 목차 코드 | `AASSOCNOTE` 코드가 69개사에서 고정이다. 금융과 비금융은 II장에서만 갈리고 나머지 11개 장은 같다 |
| 3 | 레이어 적용 방법 | 0~2걸음은 모델이 코드 56개 중에서 고르고, 3걸음은 검색이 맡는다. 생성이 아니라 선택으로 만든다 |
| 4 | 주제별 매핑 표 초안 | 주제 20개에 1순위·보조 코드를 붙인 표다. 파트너가 요청한 키워드 표의 초안이다 |
| 5 | 질의어를 공시 용어로 옮기는 문제 | 절 제목만으로는 31%만 닿는다. 코드에 설명을 붙여 보완하고, 그 설명은 빈도 집계로 자동 생성한다 |
| 부록 A | 용어가 어느 파트에 나오는가 | 용어 20개가 12개 장에 나오는 보유율과 밀도. 4절 표를 만든 근거다 |
| 부록 B | 용어의 세 가족 | 재무제표 계정·사업 활동·지배구조로 갈린다. 매출만 세 가족 어디에도 안 속하고 전부를 관통한다 |
| 부록 C | III장 밖의 서술과 재무 수치의 연결 | 재무제표 값이 II장 74.6%, IV장 79.7%에 그대로 등장한다. 다만 연결·별도 기준은 절반이 안 적혀 있어 숫자 대조로 판정해야 한다 |
| 부록 D | 최초 작성분 결론 | 계정명 하나로 여러 장을 관통할 수 있다는 첫 결론. 기록으로 남긴다 |
| 부록 E | III-8 기타 재무에 관한 사항의 구조 | 중분류 소제목이 32~65종으로 흔들려 제목으로 자를 수 없다. 3층이 어려운 이유다 |
| 부록 F | DART XML 의 기계 이름표 | 표에는 코드가 붙어 있으나 II 사업의 내용·IV 경영진단·X 대주주 거래에는 하나도 없다 |
| 부록 G | 측정의 한계 | 무엇을 재지 않았는지 |
| 부록 H | 데이터 분할과 정보 판단 프로세스 | 세 축 분할, 5단계 판단, 평가에서 드러난 실패 13유형, 값의 기준일 판별 |

# 1. 요약

## 1-1. 물어본 것

질의 패턴을 목차에 연결하는 표를 만들 수 있는가. 만들 수 있다면 어떤 형태인가.

## 1-2. 답

세 층으로 갈린다. 층마다 확실성이 다르고 담당도 달라야 한다.

| 층 | 무엇을 정하는가 | 고정성 | 방법 |
|---|---|---|---|
| 1층 | 어느 장인가 (I~XII) | 69개사 100% 동일 | 코드로 결정 |
| 2층 | 어느 절인가 | 금융/비금융만 갈림 | 코드로 결정 |
| 3층 | 절 안 어디인가 | 기업마다 다름 | 검색. 코드로 못 자름 |

1층과 2층은 사전도 판단도 필요 없다. `AASSOCNOTE` 라는 코드가 원문에 박혀 있고
69개사에서 같다. 조회하면 끝난다.

3층이 실제 문제다. 여기는 표기 변형이 32~65종이라 제목으로 자를 수 없다.

## 1-3. 그래서 표는 이렇게 만든다

주제마다 1·2층 코드를 지정하고, 3층은 코드 대신 검색에 넘긴다.
4절이 그 표의 초안이다.

## 1-4. 확인된 사실 넷

```
목차 코드가 69개사에서 고정      D- 계열 전부 동일. 금융/비금융은 II장에서만 갈림
계정명 하나가 여러 장을 관통      "매출" 은 12개 장 중 11곳에 등장
기계 이름표가 안 닿는 장이 있다   II 사업의 내용 · IV 경영진단 · X 대주주 거래
연결이 숫자로 검증된다           재무제표 매출액이 II 본문에 74.6%, IV 본문에 79.7% 그대로 등장
```

셋째 줄이 중요하다. 코드만으로는 정성 질의의 핵심 근거에 못 간다.

# 2. 목차 코드 — 대분류는 원문에 박혀 있다

## 2-1. 실측

2025 사업보고서 69건 전수다 (2026-08-30).

```
기업당 코드 개수    49종 8개사(전부 금융) · 51종 58개사 · 56종 3개사
전체 고유 코드      56종
제목 표기가 한 가지로 고정된 코드   44종
```

원문에서 이렇게 생겼다.

```
<TITLE ATOC="Y" AASSOCNOTE="D-0-1-3-0" ATOCID="6">3. 자본금 변동사항</TITLE>
```

`AASSOCNOTE` 가 의미 코드이고 `ATOCID` 는 문서 내 일련번호다. 코드 쪽이 기업 간
공통이므로 매핑에는 이것을 쓴다.

## 2-2. 갈리는 지점은 II장 하나뿐

| 코드 계열 | 해당 | 내용 |
|---|---|---|
| `D-` 계열 | 69/69 전 기업 동일 | I·III·IV·V·VI·VII·VIII·IX·X·XI·XII 전부 |
| `L-0-2-*-L1` | 비금융 61개사 | II장 하위 7개 절 |
| `L-0-2-*-L2` | 금융 8개사 외 3개사 | II장 하위 5개 절 |

나머지 11개 장은 금융이든 비금융이든 같다. 분기 처리는 II장에만 두면 된다.

# 3. 레이어를 어떻게 적용할 것인가

## 3-1. 탐색 순서

질문이 들어와서 근거를 찾기까지 네 걸음이다.

```
0  질의어를 공시 용어 쪽으로 옮긴다      "주주환원" 은 배당 얘기다
1  어느 장인가                      III. 재무에 관한 사항
2  어느 절인가                      D-0-3-6-0  6. 배당에 관한 사항
3  절 안 어디인가                    "주당 배당금" 이 있는 표
```

0~2 걸음이 후보를 좁히고, 3 걸음이 값을 찾는다. 앞을 건너뛰면 전문 검색이 되어
정확도가 떨어지고, 뒤를 건너뛰면 절은 찾았으나 값을 못 찾는다.

## 3-2. 걸음마다 담당이 다르다

이게 설계의 핵심이다. 전부를 사전으로 잡으려 해도, 전부를 모델에 맡겨도 무너진다.

| 걸음 | 담당 | 이유 |
|---|---|---|
| 0·1·2 | 모델이 코드 56개 중에서 고른다 | 목록이 닫혀 있어 없는 절을 만들 수 없다 |
| 3 | BM25 + 벡터 검색 | 표기 변형이 많아 사전으로 못 잡는다 |

0~2 걸음에서 모델에게 자유 문자열을 쓰게 하지 않는다. 코드 56개를 선택지로 주고
그중에서 고르게 한다. 생성이 아니라 선택이다.

이 방식의 이점은 셋이다.

```
없는 절을 만들 수 없다             선택지에 없으면 못 고른다
번역 사전이 따로 필요 없다          "전속 연예인" 을 절에 붙이는 것 자체가 번역이다
틀렸을 때 어디서 틀렸는지 보인다     고른 코드를 남기면 된다
```

## 3-3. 별도 매칭 사전을 만들 것인가

세 방향을 놓고 봤다.

| 방향 | 장점 | 단점 |
|---|---|---|
| 우리가 사전을 만든다 | 결정론적. 검증 가능 | 평가 질의가 비공개다. 예상 못 한 표현은 0건이 된다 |
| 모델에 전부 맡긴다 | 새 표현에 대응 | 없는 절·없는 계정명을 만들어낸다 |
| 코드 목록을 선택지로 주고 고르게 한다 | 커버리지와 안전을 동시에 | 목록 밖 주제는 여전히 못 잡는다 |

셋째를 택하는 것이 맞다고 본다. 첫째와 둘째의 절충이 아니라, 사전을 새로 만드는
대신 이미 원문에 있는 목록을 선택지로 쓰는 것이다.

다만 코드 목록만 주는 것으로는 부족하다. 제목만으로 질의에 닿는 비율이 31% 라
나머지는 모델이 의미로 이어야 하는데 그 능력이 검증되지 않았다. 코드에 설명을
붙여 단어 대조에 가깝게 만드는 보완이 필요하다. 한계와 보완책은 5-3·5-4 절에 적었다.

그러면 사실 계층에 매칭 전용 파일을 따로 둘 필요가 없다. 코드 56개와 제목이
그 파일의 역할을 한다.

## 3-4. 그래도 표가 필요한 이유

사전으로는 안 쓰지만 few-shot 재료로는 필요하다.

모델이 코드를 잘 고르려면 예시가 있어야 한다. 4절의 주제별 표가 그 예시가 된다.
사전이 아니라 학습 재료라는 점이 다르다. 사전은 없으면 0건이 되지만, 예시는
없어도 모델이 고른다. 다만 정확도가 떨어진다.

## 3-5. 3층은 왜 코드로 못 자르는가

3층은 절 안쪽이다. 여기에는 코드가 없다. III-8 기타 재무에 관한 사항의 중분류
소제목은 표기 변형이 32~65종이라 제목으로도 자를 수 없다 (부록 E).

그래서 3층은 검색이 맡는다. BM25 와 벡터를 섞어 절 안에서 찾는 방식이고,
본문 청크가 있어야 하므로 W6 본문 계층이 선행이다.

한 가지 오해를 미리 걷어둔다. 표가 없는 절이라고 해서 뽑을 것이 없는 것은 아니다.
사업의 개요는 표가 0개지만 자연어 문단이 9개, 평문 1,922자다 (삼성전자 실측).
어휘를 뽑을 때 표만 보면 이 구간을 통째로 놓친다. 5-4 절에 표와 문단을 나눠 잰
결과를 적었다.

# 4. 주제별 매핑 표 — 초안

부록 A 의 밀도 측정에 2절의 코드를 붙인 것이다. 밀도 5회 미만인 장은 뺐다.

`1순위` 는 값이 실제로 있는 자리, `보조` 는 설명이나 맥락이 있는 자리다.

| 주제 | 1순위 | 보조 | 각 자리가 담당하는 것 |
|---|---|---|---|

사업의 개요에서 뽑힌 13종이 글로벌 · 시장 · 기술 · 제품 · 국내 같은 일반어인 이유가
이것이다. 기업마다 하는 사업이 다르니 30개사 공통으로 남는 말은 일반어밖에 없다.
필터를 고쳐도 이건 안 바뀐다. 데이터의 성질이다.

다만 이 절은 설명이 약해도 괜찮다. 제목이 사업의 개요이고 질의도 어떤 사업을 하는지
쪽이라 제목만으로 닿는 몇 안 되는 절이다.

즉 두 방식이 서로 빈 곳을 메운다. 제목이 안 겹치는 것은 배당·주주 같은 절인데 그쪽은
어휘 추출이 잘 되고, 어휘 추출이 약한 것은 사업의 개요인데 그쪽은 제목이 겹친다.

합치면 커버리지가 오르지만 얼마나 오르는지는 호출해봐야 안다.

# 부록 C. III장 밖의 서술이 재무 수치와 이어지는지 — 숫자 대조로 판단

무엇을 확인한 것인가. 사업보고서의 재무 수치는 III. 재무에 관한 사항에 있는데,
그 수치를 설명하는 문장은 II. 사업의 내용과 IV. 이사의 경영진단에 흩어져 있다.
그 서술이 정말 같은 수치를 다루는 것인지를 숫자 대조로 확인한 기록이다.

이것이 확인되면 재무 질의에 III장만 보지 않고 II·IV장의 설명을 함께 근거로 쓸 수 있다.

단어가 겹친다는 것만으로는 같은 얘기인지 알 수 없다. 그래서 재무제표의 매출액 값이 서술 본문에 같은 숫자로 나오는지 대조했다.

| 대상 | 등장 | 미등장 | 등장률 |
|---|---|---|---|
| II. 사업의 내용 | 44 | 15 | 74.6% |
| IV. 이사의 경영진단 | 47 | 12 | 79.7% |

실제 사례다. 왼쪽이 재무제표 값, 오른쪽이 서술 본문에서 찾은 문장이다.

```
삼성전자   333,605,938 백만원
  II장  "2025년 당사의 매출은 333조 6,059억원으로 전년 동기 대비 10.9% 증가하였으며,
         주요 매출처는 Alphabet, Apple, Deutsche Telekom …"
  IV장  "제57기 당사 매출액은 전년 대비 32조 7,350억원(10.9%) 증가한 333조 6,059억원을
```

## C-1. 재무 사항 밖의 수치는 연결인지 별도인지 밝혀져 있지 않다

II·IV장의 서술을 근거로 쓰려면 그 수치가 연결 기준인지 별도 기준인지 알아야 한다.
같은 항목이라도 두 값이 다르기 때문이다. 그런데 그 표기가 절반 가까이 없다.

비금융 30개사 실측이다 (2026-08-30). 각 절 안에 "연결 기준" · "별도 기준" 같은
표기가 나오는지를 셌다.

| 절 | 보유 | 연결만 | 별도만 | 둘 다 | 표기 없음 |
|---|---|---|---|---|---|
| II-1 사업의 개요 | 30 | 11 | 1 | 1 | 17 |
| II-4 매출 및 수주상황 | 30 | 10 | 5 | 1 | 14 |
| IV-3 재무상태 및 영업실적 | 30 | 16 | 0 | 8 | 6 |
| IV-4 유동성 및 자금조달 | 30 | 10 | 2 | 5 | 13 |

II장은 절반 넘게 기준 표기가 없다. IV장은 그나마 나은데, 대신 한 절 안에 연결과
별도가 함께 나오는 경우가 8건이라 어느 문장이 어느 기준인지 다시 갈라야 한다.

앞의 세 사례에서도 갈렸다. LG이노텍만 "연결 기준 매출액은" 이라고 밝혔고,
삼성전자와 SK하이닉스는 기준을 적지 않았다.

### 그래서 표기 대신 숫자로 판정한다

기준이 안 적혀 있어도 값은 하나로 정해진다. 재무제표의 연결 값과 별도 값을 둘 다
구해놓고 본문 숫자와 대조하면 어느 쪽인지 확정된다.

```
삼성전자 2025 매출액
  연결  333,605,938 백만원
  별도  238,043,009 백만원
  II장 본문 "333조 6,059억원"  → 연결로 확정
```

두 값이 우연히 같은 경우가 아니면 이 방법이 확실하다. 종속회사가 없어 연결과 별도가
같은 기업에서는 판정이 안 되지만, 그 경우는 어느 쪽으로 답해도 값이 같다.

### 답변에 쓸 때

기준이 안 적힌 서술을 근거로 인용할 때는 우리가 판정한 기준을 함께 밝힌다.
원문에 없는 말을 덧붙이는 것이 아니라, 어느 재무제표 값과 일치하는지를 표시하는 것이다.

```
안 좋음   II장에 "매출 333조 6,059억원" 이라고 기재되어 있습니다
좋음      II장에 "매출 333조 6,059억원" 으로 기재되어 있으며,
          이 값은 연결 손익계산서의 매출액과 일치합니다
```

## C-2. 표기 형식이 기업마다 다르다

원 단위 그대로 쓰기도 하고(SK하이닉스 97,146,675), 조·억 단위로 바꾸기도 한다(삼성전자 333조 6,059억원). 따라서 대조할 때 표기 변환 후보를 여러 개 만들어 비교해야 한다.

```
억 단위             3,336,059억 · 3,336,059억원
백만원 환산          333,605
```

# 부록 F. DART XML 의 기계 이름표
2절과 4절에서 쓴 용어를 정리한다.

공시 원문 XML은 웹페이지 소스와 비슷하다. 값마다 꼬리표가 붙는다.

```xml
<TABLE-GROUP ACLASS="{XBRL}BS_C">                       ← 이 표는 연결 재무상태표다
  <TITLE>2-1. 연결 재무상태표</TITLE>
  <TE ACODE="ifrs-full_Inventories">52,636,828</TE>     ← 이 칸의 숫자는 재고자산이다
</TABLE-GROUP>
```

| 표기 | 뜻 |
|---|---|
| `TE` | 표의 칸 하나. 엑셀 셀에 해당 |
| `ACODE` | 그 칸에 붙은 이름표. 값이 무엇인지 알려줌 |
| `ACLASS` | 표 전체에 붙은 이름표. 그 표가 무엇인지 알려줌 |
| `SECTION-1` | 대목차 한 덩어리. I~XII장 각각 |

엑셀에 비유하면 셀마다 숨은 메모가 붙어 있는 것이다. 다만 엑셀 메모는 사람이 임의로 다는 반면 이 이름표는 DART 서식이 강제해서 기업이 달라도 같은 이름표가 붙는다.

## F-1. 이름표가 없는 파트가 있다

2025 사업보고서 69건 전수 측정이다.

| 파트 | 이름표가 붙은 칸 |
|---|---|
| I 개요 · V 감사 · VI 이사회 · VII 주주 · VIII 임원 · IX 계열 · XI 기타 · XII 상세 | 100% |
| III 재무 | 75.1% |
| II 사업의 내용 | 칸 자체가 0개 |
| IV 이사의 경영진단 | 칸 자체가 0개 |
| X 대주주 등과의 거래내용 | 칸 자체가 0개 |

II · IV · X 세 파트는 기계 이름표로 접근할 수 없다. 이 문서가 단어 기반 연결을 다루는 이유다.

## F-2. 파트마다 이름표 체계가 다르다

```
III   ifrs-full_Revenue · ifrs-full_Inventories       → IFRS 회계 계정 체계
I     CS_DIV · CS_BPP · NEW_CPY                       → DART 서식 필드 체계
VII   SH5_NM_T · SH5_BGN_CNT · STK_KND
VIII  SH5_PER · SH5_LEV · SH5_OBJ
```

두 체계는 공통 코드가 없다. 이름표만으로 파트를 가로질러 잇는 것은 불가능하고, 그래서 단어가 필요하다.

## F-3. 재무제표에 주석 번호 참조가 없다

종이 재무제표에는 "주석 6 참조" 표기가 있지만 이 코퍼스의 DART XML에는 없다. 비금융 2025 사업보고서 61건 전수에서 0건이었다.

```
삼성전자 연결 재무상태표 헤더 : ['', '제 56 기', '제 55 기', '제 54 기']
```

계정명과 3개년 금액뿐이다. 재무제표와 주석을 잇는 명시적 연결선이 없어서 계정명 대조가 필요하다.

## F-4. 계정명 대조로 재무제표와 주석이 이어진다

비금융 2025 사업보고서 61건, 주요 계정 기준이다.

| 계정 | 주석 제목에 같은 이름 등장 |
|---|---|
| 유형자산 · 무형자산 · 재고자산 | 100% |
| 차입금 · 충당부채 | 98% |
| 관계기업 | 96% |
| 리스 | 94% |
| 매출채권 | 92% |
| 기타채권 | 88% |

공백과 기호만 제거하고 비교하면 된다. `매출채권및기타채권`과 `매출채권 및 기타채권`을 같게 취급하는 수준이다.

# 부록 G. 측정의 한계
단어가 등장한다는 것과 맥락이 이어진다는 것은 다르다. 매출이 VIII 임원 파트에 54% 기업에서 나오지만 밀도가 9회다. "매출액 대비 보수" 같은 맥락일 가능성이 크고, 매출 질의에 그대로 끌어오면 답이 흐려진다. 등장은 후보일 뿐 유의미성은 별도 판정이 필요하다.

숫자 대조 등장률 74.6%와 79.7%는 표기 변환 후보를 6종으로 잡은 결과다. 후보를 늘리면 올라가고, 반올림 자릿수가 다르면(예: 억원 미만 반올림) 못 잡는다.

III-8 중분류 제목 추출은 완전하지 않다. 제목이 태그로 마크업되어 있지 않아 문단 패턴으로 잡았고, 본문 문장이 번호로 시작하는 경우를 완벽히 구분하지 못했다.

측정 대상이 비금융 2025 사업보고서다. 금융 8개사와 다른 연도는 2절·4절 측정에 포함되지 않았다.

# 부록 H. 데이터 분할과 정보 판단 프로세스
평가지 28문항(기본 22 + 자체제작 6)을 실제로 풀고 3차에 걸쳐 피드백을 받은 결과를 설계로 정리한다. 앞 절들의 측정치와 평가에서 드러난 실패 사례를 함께 반영했다.

## H-1. 데이터를 나누는 기준 — 세 축

측정으로 확인된 성질에 따라 세 축으로 나눈다. 축마다 처리 방식이 다르다.

### 축 1. 문서 크기와 정형성

| 유형 | 건수 | 평균 크기 | 처리 |
|---|---|---|---|
| 거래소공시 | 1,469 | 0.01 MB | 문서 하나가 청크 하나. 통째로 투입 |
| 주요사항보고서 | 598 | 0.04 MB | 문서 하나가 청크 하나. 유형별 스키마 33종 |
| 지분공시 | 1,083 | 0.20 MB | 대부분 통째로. 첨부가 큰 건만 분할 |
| 정기공시 | 1,054 | 2.8~7.9 MB | 반드시 분할. HCX 한도의 10~20배 |

건수로는 정기공시가 25%인데 용량으로는 대부분을 차지한다. 분할이 필요한 것은 정기공시뿐이다.

### 축 2. 정기공시 내부 — 고정층과 자유층

| 층위 | 고정성 | 분할 방법 |
|---|---|---|
| 대목차 14개 (I~XII장) | 70개사 100% 동일 | `SECTION-1` 제목으로 결정론적 절단 |
| 중목차 (III-1~8 등) | 대부분 고정 | `SECTION-2` 제목으로 절단 |
| 표 | ACLASS 코드 부여 | 코드로 직접 지정 |
| 중분류 소제목 (III-8 내부 등) | 기업마다 다름 | 절단 기준 없음. 키워드 검색 |

경계를 어디에 둘지는 이 표가 결정한다. 위 세 줄까지는 코드나 제목으로 자르고, 맨 아랫줄은 자르지 않고 통째로 두는 편이 낫다.

### 축 3. 값의 성격

| 성격 | 저장 | 검증 방법 |
|---|---|---|
| 정량 (계정 금액) | 사실 테이블 (계정 × 컨텍스트 × 값) | 단위·기간·연결여부를 속성으로 확정 |
| 정성 (서술) | 섹션 단위 텍스트 | 숫자 대조로 관련성 확인 (4절) |
| 이벤트 (계약·조달) | 라벨-값 사실 행 | 라벨 사전으로 추출. 94.2% 회수 |

## H-2. 정보 판단 프로세스 — 5단계

평가에서 실패한 지점을 되짚으면 단계가 다섯으로 갈린다. 각 단계에서 무엇이 결정되고 어떤 실패가 일어나는지를 함께 적는다.

```
0단계  질의어를 공시 용어로 번역
1단계  대상 문서 특정          (기업 · 기간 · 문서 유형)
2단계  문서 안의 위치 특정      (파트 · 표 · 중분류)
3단계  값 추출과 검증
4단계  답변 구성과 한계 표기
```

### 0단계 — 질의어를 공시 용어로 번역

사용자 말과 공시 용어가 다르다. 평가에서 세 번 걸렸다.

| 사용자 표현 | 공시 표기 | 문항 |
|---|---|---|
| 전속 연예인 | 전속계약금 (무형자산 하위 계정) | 자체 4 |
| 이재용 회장 | 이재용 (직함 없음) | 자체 1 |
| 삼성 그룹 | 존재하지 않음. 계열회사 현황으로 우회 | 자체 1 |
| 90일 이상 연체 | 경과기간 구간에 없음. 최소 6개월 | 자체 3 |

이 단계를 건너뛰면 검색이 0건을 반환하고, 그것을 "데이터 없음"으로 오해한다. 실제로는 용어가 안 맞았을 뿐이다.

### 1단계 — 대상 문서 특정

`manifest.jsonl`의 16개 공통 필드로 처리된다. 검색이 아니라 조회다.

주의할 점 셋이다.

기업명이 세 갈래로 지칭된다. 현대차/현대자동차, KT/케이티, 엔씨소프트/NC, 삼성화재/삼성화재해상보험, LS ELECTRIC/엘에스일렉트릭, LIG넥스원/LIG디펜스앤에어로스페이스 6개사가 통용명과 법인명이 다르다.

별칭 테이블은 만들지 않는다. `docs/SCHEMA.md`가 `company` 테이블의 `corp_name`·`listed_name`·`sector` 세 컬럼 조회로 해결하기로 정했고, 세 컬럼 모두 제공 데이터 안의 값이다. 시장 은어(포스코·하이닉스 등)는 코퍼스 어디에도 없고 평가 규칙이 외부 데이터 추가를 금지한다.

비정기공시는 `base_year`가 전부 비어 있다. 연도 필터는 `rcept_dt`나 본문 사건일자로만 가능하고, 접수일과 사건 발생일이 다를 수 있다.

문서가 없는 것과 정보가 없는 것은 다르다. 자체 1에서 삼성물산 사업보고서는 코퍼스에 없지만, 다른 계열사의 "최대주주의 최대주주" 항목에 삼성물산의 최대주주가 기재되어 있었다. 문서 부재를 정보 부재로 단정하면 답할 수 있는 것을 못 답한다.

### 2단계 — 문서 안의 위치 특정

2절과 5절의 용어별 파트 매핑을 쓴다. 밀도 5회 미만 파트는 후보에서 뺀다.

이 단계의 함정은 표 제목 표기 변형이다.

```
삼성전자 · 삼성E&A · 삼성화재 · 삼성중공업
  → "최대주주 및 그 특수관계인의 주식소유 현황"
삼성생명
  → "주요주주 및 그 특수관계인의 구성"
```

자체 1에서 삼성생명의 이재용 지분 10.44%를 놓친 직접 원인이 이것이다. 가장 큰 지분이었다. 제목 완전일치로 찾으면 안 되고 "주주"와 "지분율" 같은 부분 문자열로 잡아야 한다.

III-8 중분류는 표기 변형이 32~65종이므로(6-2절) 제목으로 자를 수 없다. 이 구간은 파트 전체를 컨텍스트로 넣는 편이 낫다.

### 3단계 — 값 추출과 검증

정량은 세 가지를 확정해야 값이 된다.

```
단위      ADECIMAL (-6 백만원 · -3 천원 · 0 원)
          비금융은 천원과 백만원이 반반이라 놓치면 1,000배 오차
기간      ACONTEXT 앞부분 (CFY 당기 · PFY 전기 · BPFY 전전기)
연결여부   ACONTEXT 축 부분 (ConsolidatedMember · SeparateMember)
```

정성은 숫자 대조로 검증한다. 재무제표 값이 서술 본문에 같은 숫자로 나오면 그 문단이 그 계정을 다룬다는 것이 확정된다. II 74.6%, IV 79.7%다.

검증이 안 되는 25%는 단어 매칭까지만 된 상태이므로 답변에 그 사실을 밝힌다.

### 4단계 — 답변 구성과 한계 표기

여기서 실패한 사례가 가장 많았다.

## H-3. 평가에서 드러난 실패 유형 13가지

| # | 실패 | 사례 | 방지 규칙 |
|---|---|---|---|
| 1 | 한 곳만 보고 없다고 단정 | 자체 1 — 삼성전자만 보고 지배구조 불가 판정 | 대상 기업 집합을 먼저 확정하고 전수 조회 |
| 2 | 묻지 않은 것을 답함 | 자체 1 — 오너 일가 합계 4.62% 계산 | 질의가 지목한 주체·항목 밖은 참고로 분리 |

| 13 | 값의 기준일을 확인하지 않고 최신으로 간주 | 자체 1 — 삼성물산 지분율 7개 시점 중 옛 값 채택 | 값마다 기준일을 뽑아 정렬. 9-7절 |

### 11번을 따로 두는 이유

자체 6에서 CJ제일제당 사업보고서를 "유상증자"로 검색하면 5건이 걸린다. 정답은 0건이다. 오탐률 100%다.

| 등장 자리 | 실제 주체 |
|---|---|
| 정관 제9조의4 신주의 배당기산일 | 조항 문구. 사건이 아님 |
| 종속기업·관계기업 투자 주석 (2건) | 타법인 유상증자에 출자한 것 |
| III-7 종속회사 자금 사용내역 (2건) | 종속회사 씨제이바이오사이언스의 2023·2024년 증자 |

문자열이 걸렸다고 그 회사가 그 행위를 한 것이 아니다. 셋 다 다른 얘기다. 정관은 규정, 투자 주석은 남의 증자에 참여, 자금 사용내역은 종속회사 증자다.

따라서 키워드 매칭 뒤에 주체 확인 단계가 필요하다.

```
확인 순서
  1  키워드가 걸린 문단의 주체가 질의 대상 기업인가
  2  주체가 종속회사·관계회사면 그 사실을 명시하고 본체 사건과 구분
  3  정관·회계정책 등 규정 서술이면 사건 근거에서 제외
  4  시점이 질의 기간 안인가
```

이 검증은 코드로 가능하다. 주체를 판별하는 단서가 문단 안에 있다. "종속회사", "당사의 종속기업", 회사명 등이 그것이다.

## H-4. 근거 표시 규칙

피드백에서 두 번 지적된 사항이다. 규칙으로 고정한다.

### 최소 단위는 중분류까지

```
[출처] 효성중공업 사업보고서 (2025.12) · 접수번호 20260311004208
         III. 재무에 관한 사항 > 2. 연결재무제표 > 연결 손익계산서   (매출액·영업이익)
         II. 사업의 내용 > 1. 사업의 개요                        (사업 구성)
```

보고서명과 접수번호까지만 적으면 검증이 안 된다. 어느 대목차의 어느 중분류를 봤는지 적고, 여러 곳을 참고했으면 전부 적는다. 각 출처가 무엇을 제공했는지 괄호로 붙이면 대조가 쉬워진다.

### "없음"의 근거에도 출처를 붙인다

```
[출처] 확인 대상 : 코스닥 9개사 2025 사업보고서
         III-8 > 경과기간별 매출채권 잔액 현황       7개사
         연결재무제표 주석 > 매출채권 연령분석        1개사
         해당 표 없음                             1개사
       오인 방지용으로 함께 확인한 자리
         III-7 > 기업어음증권 미상환 잔액 (잔여만기 90일 구간, 채권 연체와 무관)
```

없다는 결론일수록 어디를 봤는지가 중요하다. 그렇지 않으면 안 찾은 것과 구분되지 않는다. 답에 쓰지 않은 자리도 확인했다면 적는 편이 낫다. 왜 그것을 근거로 삼지 않았는지가 함께 설명된다.

## H-5. 정보량 조절

전부 가져오면 읽히지 않고, 적게 가져오면 부실하다. 질의 유형별 기준을 둔다.

```
질의가 "현황을 알려줘" 류    → 요약까지. 상세표는 위치만 안내
질의가 특정 대상을 지목      → 그 행만 상세표에서 발췌
질의가 "모두"를 요구         → 전건 목록 + 요약 + 상세표는 건수만 제시
```

보조 섹션은 2개까지, 각 섹션에서 문단 1개 또는 표 1개까지로 제한한다. 우선순위는 2-1절의 밀도 순으로 정한다.

## H-6. 교차 확인 경로

한 다리로만 확인한 결론은 약하다. 대응 항목이 있으면 양쪽을 본다.

| 확인 대상 | 1차 | 2차 |
|---|---|---|
| 유상증자·자본 변동 | 주요사항보고서 발행결정 | I-3 자본금 변동사항 · III-7 증권 발행을 통한 자금조달 |
| 배당 | III-6 배당에 관한 사항 | 자기주식 관련 주요사항보고서 |
| 설비투자 | 거래소공시 신규시설투자등 | II-3 원재료 및 생산설비 · 연결현금흐름표 유형자산 취득 |
| 계약 | 거래소공시 계약체결·해지 | II-4 매출 및 수주상황 |
| 연구개발 | II 연구개발활동 | 거래소공시 임상 관련 · 무형자산 주석 개발비 |
| 동일 연도 수치 | 해당 연도 사업보고서 | 이후 연도 보고서의 전기·전전기 열 |

마지막 줄이 특히 유용하다. 같은 연도 값이 세 보고서에 실리므로 세 값이 일치하면 그 자체가 검증이고, 어긋나면 정정이나 소급재작성 신호다.

방향에는 주의가 필요하다. 정기공시를 1차로 두면 조회가 빠르지만, 최신 분기보고서 기준일 이후의 사건은 반영되지 않아 누락이 생긴다. 최신 시점을 묻는 질의는 이벤트 공시를 1차로 두는 편이 안전하다.

## H-7. 값의 기준일 — 최신 판별

같은 항목의 값이 여러 시점으로 흩어져 있다. 무엇이 최신인지는 값만 봐서 알 수 없다.

### 실측 사례

삼성물산의 최대주주(이재용) 지분율이 코퍼스 안에 일곱 시점으로 나온다. 네 개 회사의 사업보고서에 흩어져 있다.

| 기준일 | 지분율 | 어느 문서의 어디 |
|---|---|---|
| 2021-04-29 | 18.13% | 삼성바이오로직스 · 변동내역 표 |
| 2023-04-21 | 18.26% | 〃 |
| 2024-04-19 | 19.06% | 〃 |
| 2025-02-05 | 19.93% | 〃 |
| 2025-09-30 | 19.76% | 삼성화재 · 표 아래 주석 |
| 2025-12-31 | 19.93% | 삼성전자 · 표 아래 주석 |
| 2026-01-02 | 21.00% | 삼성전자 · 표 아래 본문 문장 |

값이 19.93 → 19.76 → 19.93으로 오르내린다. 큰 값이 최신이라는 규칙도, 마지막에 나온 값이 최신이라는 규칙도 성립하지 않는다. 기준일을 각각 뽑아 정렬해야만 판별된다.

### 문제 1 — 기준일이 값 옆에 없다

네 문서가 전부 다른 자리에 다른 형식으로 적는다.

```
삼성전자     표 아래 주석          ※ 2025년 12월 31일, 보통주 기준입니다
삼성화재     표 아래 주석 (다른 기호) 註) 삼성물산이 공시한 제62기 3분기보고서 기준임 ('25.9.30 기준)
삼성바이오   변동내역 표의 행 레이블  2025.02.05 | 이재용 | 19.93
삼성전자     본문 문장 안          2026년 1월 2일 … 제출일 기준 … 21.00%입니다
```

표에 기준일 칸이 있는 것이 아니라 표 밖에 흩어져 있다. 값을 뽑아도 기준일이 딸려오지 않는다.

가장 최신값 21.00%는 아예 표 안에 없다. 표 아래 문장으로만 있다. 표만 파싱하면 놓친다.

### 문제 2 — 문서 접수일로 판단하면 틀린다

| 문서 | 접수일 | 담고 있는 값의 기준일 |
|---|---|---|
| 삼성전자 사업보고서 | 2026-03-10 | 2025-12-31 |
| 삼성화재 사업보고서 | 2026-03-12 | 2025-09-30 |

삼성화재가 이틀 늦게 접수됐는데 값은 석 달 오래됐다. 남의 회사 분기보고서를 인용했기 때문이다. 문서가 새것이라고 값이 새것이 아니다.

`manifest.jsonl`의 `rcept_dt`로 최신을 고르는 방식이 이 지점에서 무너진다.

### 문제 3 — 상대 표기가 섞인다

21.00%의 기준일은 "제출일"이다. 절대 날짜가 아니라 그 문서의 제출일을 가리킨다. 문서 메타데이터의 접수일과 결합해야 실제 날짜가 된다.

같은 계열로 "작성기준일 현재", "보고서 제출일 현재", "최근 사업연도말" 등이 쓰인다.

### 해결 — 값을 세 쌍으로 저장한다

```
(값, 기준일, 출처)

19.93%  2025-12-31  삼성전자 사업보고서 VII-2 최대주주의 최대주주
19.76%  2025-09-30  삼성화재 사업보고서 VII-2 (삼성물산 3분기보고서 인용)
21.00%  2026-03-10  삼성전자 사업보고서 VII-2 주석 ("제출일 기준" → 접수일로 해석)
```

이렇게 만들어두면 최신 선택은 `max(기준일)` 한 줄이다. 날짜 비교 자체는 코드가 완벽하게 한다. 어려운 것은 두 번째 칸을 채우는 일이고, 그건 규칙으로 지정해야 한다.

### 기준일 추출 규칙

```
1  표 헤더의 "(기준일 : YYYY년 MM월 DD일)" 표기       → 그 표 전체에 적용
2  표 아래 ※ 註 주석의 "…기준입니다" 문장             → 직전 표에 적용
3  변동내역 표의 첫 열 날짜                           → 그 행에만 적용
4  "제출일 기준" · "작성기준일 현재" 등 상대 표기      → 문서 접수일로 치환
5  위 어느 것도 없으면                                → 기준일 미상으로 표시하고
                                                      최신 후보에서 제외
```

5번이 중요하다. 기준일을 못 찾은 값을 최신으로 잘못 고르는 것보다, 미상으로 빼고 답변에 밝히는 편이 안전하다.

### 모델에게 맡길 수 있는가

읽어내기는 한다. 다만 위 사례처럼 같은 값이 두 시점에 나오고 중간에 더 낮은 값이 끼면 흔들린다. 실제로 이 문항의 1차·2차 풀이가 연속으로 틀렸다.

역할을 나누는 편이 안전하다.

| 단계 | 담당 |
|---|---|
| 기준일 추출 | 코드 (위 5개 규칙) |
| 최신 선택 | 코드 (정렬) |
| 값의 의미 설명 | 모델 |

### 답변에 쓸 때

기준일이 다른 값을 함께 제시할 때는 어느 것이 확정 기준일이고 어느 것이 주석 언급인지 구분한다.

```
지분율은 2025-12-31 기준 19.93%이며, 2026년 1월 2일 증여를 반영한
보고서 제출일 기준으로는 21.00%입니다.
```

21.00%를 앞세우지 않은 이유는 기준일이 상대 표기이고 그 시점의 원 공시가 코퍼스에 없기 때문이다. 확정 기준일이 있는 값과 주석으로만 언급된 값은 구분해 두는 편이 안전하다.

## H-8. 신뢰도 구분 표기

단계마다 재현성이 다르다. 답변에 섞어 쓰면 어디까지 믿을 수 있는지 알 수 없다.

| 층 | 방법 | 재현성 | 표기 |
|---|---|---|---|
| A | 코드 직접 조회 (ACLASS · ACODE · manifest 필드) | 완전 | 근거를 그대로 제시 |
| B | 숫자 대조로 검증된 서술 | 완전 | 대조한 값을 함께 제시 |
| C | 용어 매칭만 된 서술 | 부분 | "관련 서술로 보이나 수치 대조로 확인하지 못함" |
| D | 모델 해석 | 없음 | 판단임을 명시 |

A와 B는 `think_trace`에 왜 그 자리를 골랐는지가 그대로 남는다. C와 D는 남지 않으므로 답변 본문에 구분을 적는다.

# 부록 I. 재현 방법
측정 스크립트는 세션 스크래치패드에 있다.

| 파일 | 역할 |
|---|---|

| `p1_termmap.py` | 용어 × 파트 분포 측정 (2절) |
| `q1_numverify.py` | 재무제표 값의 서술 본문 등장 검증 (4절) |
| `m1_sectionmap.py` | 파트별 이름표 밀도 측정 (7절) |

| `j1_sec8_struct.py` · `j3_clean.py` | III-8 구조 분석 (6절) |

파트를 잘라내는 방법이다.

```python
for m in re.finditer(r"<SECTION-1[^>]*>(.*?)(?=<SECTION-1|</BODY>|\Z)", txt, re.S):
    seg = m.group(1)
    title = re.search(r"<TITLE[^>]*>(.*?)</TITLE>", seg, re.S)
```
