# 1. 먼저 답이 필요한 셋

이 셋만 정해지면 시작할 수 있다.

## 1-1. `더할것` 낱말에 점수를 누가 어떻게 매기나

`낱말` 칸은 `낱말:점수:확률` 인데 `더할것` 은 낱말만 쉼표로 적으라고 되어 있다.

```
지금 안내    이유, 신설, 개정, 영위
```

그 낱말들의 점수를 사람이 함께 적어야 하는지, 코드가 일괄값을 주는지,
나중에 따로 매길 것인지 모르겠다.

이것이 안 정해지면 낱말을 고를 수는 있어도 "몇 개가 겹쳐야 문턱을 넘는가" 를
설계할 수 없다. `ONBOARDING.md` 8.3 은 점수 층을 셋으로 나누라고 했는데
(혼자 확정 16~25 · 짝이 필요 8~10 · 거들기 3~6), 그 지침이 새 표에도
그대로인지도 함께 알려 주면 좋겠다.

## 1-2. `더할것` 낱말이 절 본문에 없어도 되나

경로표는 질의를 절에 잇는 것이므로 낱말이 질의에만 있으면 된다고 이해했다.
그런데 점수 정의가 `(그 절 비율) ÷ (전체 비율)` 이라 본문에 없으면 정의상 0 이다.
두 관점이 충돌한다.

실제로 걸리는 사례가 있다. 비금융 30개사 3,789절 실측이다.

```
IV장 168절에서   경영진단 0.0%  ·  분석의견 0.0%
형태소 분석      "경영진단 의견"  →  ['경영', '진단', '의견']
                진단 3.6% · 의견 2.4% 로 둘 다 IV장에 드물다
```

사용자가 "경영진단 의견" 으로 물을 것은 거의 확실한데 데이터에는 없다.
`IV` 는 대분류 제목에만 그 말이 있고 그 절은 빈 껍데기라 표에서 빠져 있다.

이런 낱말을 넣어도 되는지, 넣는다면 점수를 어떻게 정할지 알려 달라.

## 1-3. 165행 중 이쪽이 맡을 범위

그쪽에서도 채우고 있는지 모르겠다. 겹치면 낭비다.

대분류로 나눌지, 열쇠종류로 나눌지 (`tag` 111개 · `title` 54개), 아니면
행 번호로 자를지 정해 주면 그대로 하겠다.

# 2. 판정에 필요한 자료

## 2-1. 용례를 볼 수 있나

`pathmap_review.csv` 에는 `용례` 칸이 있었는데 `section_schema.csv` 에는 없다.

`section_schema.md` 가 정한 판정 기준은 이것이다.

```
이 낱말이 질의에 나왔을 때, 반드시 이 절을 봐야 하는가
```

이걸 판정하려면 그 낱말이 그 절에서 어떤 문맥에 쓰이는지 봐야 한다.
`이유` 가 정관 절의 "변경이유" 칸에서 온 것을 보고서야 뺄 수 있었던 것과 같다.
낱말만 보면 뜻을 짐작해서 판정하게 되고 그러면 `이유` 사고가 되풀이된다.

작업 대상 165행에 용례를 붙여 줄 수 있는지, 아니면 이쪽에서 뽑을 방법을
알려 주면 좋겠다. 이쪽 `corpus.db` 에는 `section` · `chunk` 가 없어
원문 XML 을 직접 잘라 쓰고 있다.

## 2-2. 채점 사례와 열쇠의 대조표

`body_cases.csv` 의 `gold` 는 절 제목 문자열이라 새 표의 열쇠와 직접 안 맞는다.

```
gold   "IV. 이사의 경영진단 및 분석의견"
열쇠   재무상태및영업실적 · 개요 · 유동성및자금조달과지출 …
```

37건이 새 표의 어느 열쇠를 정답으로 하는지 이어 붙인 것이 있으면
낱말을 넣고 효과를 바로 잴 수 있다. 없으면 이쪽에서 만들어도 된다.

# 3. 결과가 검색에 어떻게 반영되는가

## 3-1. 열쇠를 조각에 어떻게 잇나

지금은 이렇다.

```
guess_paths()      경로를 돌려준다
retrieval 226행    조각의 path 와 대조한다.  path in want
```

새 표의 열쇠는 `aclass` 또는 정규화 제목이다. 대조 방식이 바뀐다.

`section.aclass` 가 전 절에 채워져 있는지, 제목 정규화는 어느 함수를 쓸 것인지
알아야 "이 낱말로 짚으면 어느 조각이 당겨지나" 를 시뮬레이션할 수 있다.
지금은 낱말을 넣고도 효과를 못 재본다.

## 3-2. 새 스케일에서 문턱

2.77배라고 했으니 단순 환산하면 41.6 이다. 그 값을 가정하고 설계해도 되는지,
아니면 표를 다 채운 뒤 다시 잴 것이라 지금은 낱말 간 상대 크기만 맞추면 되는지.

## 3-3. 상위 몇 개를 짚을 것인가

지금 `top=2` 다. 새 표는 662행이라 후보가 늘어난다. 유지인지 늘릴지에 따라
한 절에 넣을 낱말 개수 설계가 달라진다.

# 4. 결정이 필요한 것

## 4-1. IV 채점 문제 처리 방향

`TOC_SCHEMA.md` 8단계에 "처리 방향은 정하지 않았다" 로 남아 있다.
정답지는 drydye 가 만든 것이라 이쪽에서 고칠 수 있다.

```
가  grade 가 부모·자식을 인정하게 고친다 (경로 접두사 판정)
나  gold 를 실제 내용 절로 고친다 (set1-19 → IV/3 재무상태 및 영업실적)
다  그대로 둔다
```

이것이 안 정해지면 IV 관련 낱말 작업의 효과를 측정할 수 없다.
지금은 무엇을 해도 셋 다 실패로 센다.

## 4-2. `II 사업의개요` 12건을 어디서 풀 것인가

표에서 가장 약한 자리인데 채점 사례 37건 중 12건이 여기를 노린다.

```
사업의개요   기업 69 · 낱말 4개 · top 6.7
```

이쪽에서 재본 결과다. 이 절을 묻는 질의에서 남는 낱말이 `사업` `회사` 뿐인데
둘 다 전체 절의 27~37% 에 나온다. 점수를 올리면 그 낱말이 든 모든 질의가
끌려간다. 낱말 추가만으로는 안 풀릴 가능성이 크다.

`더할것` 으로 밀 것인지, 층 4 용어 확장으로 갈 것인지, 둘 다라면 경계를
어디에 둘지 알려 달라.

## 4-3. `pathmap_manual.csv` 를 어떻게 할까

`Goo` 브랜치에 4행짜리로 만들어 둔 것이 있다. 새 표와 겹친다.

```
II/1 · II/2 · III/3 · IV
```

폐기하고 낱말만 `더할것` 으로 옮기는 것이 맞아 보이는데, 그렇게 해도 되는지.
