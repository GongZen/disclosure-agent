# 평가용 API 서버 명세

제10회 2026 미래에셋증권 AI Festival — 공시 Agent

| 항목 | 값 |
|---|---|

| 프로토콜 | HTTP |
| 방식 | GET |
| 운영 기간 | 2026.09.07 ~ 09.20 상시 |

스케줄러가 API 를 다시 띄운다. 무인 재부팅 시험을 2026-09-05 에 통과했다.

## 창구 목록

| 경로 | 쓰임 |
|---|---|
| `GET /answer` | 평가 창구. 질의 하나를 받아 네 필드 JSON 을 돌려준다 |
| `GET /health` | 살아 있는지 확인 |
| `GET /docs` | 사람이 보는 명세 화면. 여기서 바로 질의를 던져 볼 수 있다 |
| `GET /openapi.json` | 기계가 읽는 명세 원본 (OpenAPI 3.1) |

`/docs` 와 `/openapi.json` 은 코드에서 자동으로 만들어진다. 이 문서와 내용이
같고, 서버가 살아 있을 때만 볼 수 있다.

## 요청

```
GET http://211.188.57.111:8000/answer
    ?question={평가 질의}
    &question_id={식별자}
    &trace={text|json}
```

| 이름 | 필수 | 기본값 | 뜻 |
|---|---|---|---|
| `question` | 필수 | 없음 | 평가 질의. 한국어 문장 |
| `question_id` | 선택 | 빈 문자열 | 질의 식별자. 받은 값을 응답에 그대로 돌려준다 |
| `trace` | 선택 | `text` | `think_trace` 를 어떤 형식으로 받을지. `text` 는 사람이 읽는 한 덩어리 글, `json` 은 단계별 구조 |

`question` 에 한글과 띄어쓰기가 들어가므로 URL 인코딩이 필요하다. 브라우저
주소창에 직접 넣으면 브라우저가 알아서 바꾼다.

### 요청 예시

```
http://211.188.57.111:8000/answer?question_id=Q-001&question=%EC%82%BC%EC%84%B1%EC%A0%84%EC%9E%90%EC%9D%98%20%EC%A3%BC%EC%A3%BC%ED%99%98%EC%9B%90%20%EC%A0%95%EC%B1%85%EC%9D%B4%20%EC%96%B4%EB%96%BB%EA%B2%8C%20%EB%90%98%EB%8A%94%EC%A7%80%20%EC%95%8C%EB%A0%A4%EC%A4%98
```

파이썬으로 부를 때는 이렇다.

```python
import json, urllib.parse, urllib.request

BASE = "http://211.188.57.111:8000"

def ask(question: str, question_id: str = "") -> dict:
    qs = urllib.parse.urlencode({"question": question,
                                 "question_id": question_id})
    with urllib.request.urlopen(f"{BASE}/answer?{qs}", timeout=120) as r:
        return json.loads(r.read().decode("utf-8"))

r = ask("삼성전자의 주주환원 정책이 어떻게 되는지 알려줘", "Q-001")
print(r["answer"])
```

## 응답

`Content-Type: application/json; charset=utf-8`

한글은 escape 하지 않고 그대로 보낸다.

```json
{
  "question_id": "Q-001",
  "question": "삼성전자의 주주환원 정책이 어떻게 되는지 알려줘",
  "retrieved_context": "[근거 1] 삼성전자 사업보고서 (2025.12) · III/6 6. 배당에 관한 사항 · 접수 2026-03-10\n가. 배당에 대한 전반적인 사항 …",
  "think_trace": "S1 질의 해석 :: {\"초\": 0.0, \"기업\": [\"삼성전자\"], …}\nS3 후보 구성 :: …",
  "answer": "삼성전자는 … \n\n근거:\n[근거 1] 삼성전자 사업보고서 (2025.12) · III/6 6. 배당에 관한 사항 · 접수 2026-03-10"
}
```

| 필드 | 형 | 뜻 |
|---|---|---|
| `question_id` | string | 받은 식별자를 그대로 돌려준다. 안 주면 빈 문자열 |
| `question` | string | 받은 질의 원문 |
| `retrieved_context` | string | 답변 생성에 실제로 넣은 공시 원문. 절 단위로 모으고 6,000자에서 자른다. 절마다 앞에 `[근거 N]` 과 출처가 붙는다 |
| `think_trace` | string 또는 array | 어떤 단계를 밟아 그 답에 이르렀는지. `trace=json` 이면 단계별 객체 배열 |
| `answer` | string | 최종 답변. 끝에 근거로 삼은 공시를 밝힌다 |

## 답을 못 하는 경우에도 네 필드가 나간다

대상 기업을 못 찾거나, 근거를 못 찾거나, 생성이 실패하거나, 처리 중 오류가
나도 HTTP 200 과 네 필드를 보낸다. `answer` 에 왜 못 했는지 적고
`think_trace` 마지막 항목에 사유를 남긴다.

평가 중 한 질의가 실패해도 나머지가 이어지도록 하기 위해서다. 오류를 HTTP
상태 코드로 알리면 평가 도구가 그 자리에서 멈출 수 있다.

```json
{
  "question_id": "Q-099",
  "question": "…",
  "retrieved_context": "",
  "think_trace": "오류 :: {\"종류\": \"…\", \"내용\": \"…\"}",
  "answer": "처리 중 오류가 발생했다."
}
```

질의 임베딩이 실패하는 경우에도 멈추지 않는다. 벡터 없이 낱말 검색만으로
계속 진행하고, `think_trace` 의 `S2 질의 임베딩` 에 그 사실을 남긴다.

## `think_trace` 의 단계

`S1` 부터 `S11` 까지가 Agent 가 질의를 처리하며 밟는 실행 단계다. 자세한 설계는
`docs/PIPELINE.md` 에 있다.

| 단계 | 하는 일 | 남기는 것 |
|---|---|---|
| `S1 질의 해석` | 질의에서 기업·연도·보고서 종류·검색어를 가른다 | 고른 기업, 연도, 검색어, 지시 조작 탐지 여부 |
| `S1-B 대상 기업 추정` | 기업 이름이 없을 때만 돈다. 그룹·업종·시장으로 대상을 정한다 | 무엇으로 골랐는지와 고른 기업 |
| `S3 후보 구성` | 그 기업들의 공시 조각을 메모리에 올린다 | 조각 수, 검색 범위, 재사용 여부 |
| `S2 질의 임베딩` | 질의를 벡터로 바꾼다 | 성공 여부. 실패하면 낱말 검색만 쓴다고 적는다 |
| `S7 본문 검색` | 낱말 검색과 벡터 검색을 합치고 매칭표로 절을 짚는다 | 찾은 절 수, 기업별 결과 수, 상위 절 이름 |
| `S7-B 범위 넓힘` | 정기공시에서 못 찾았을 때만 돈다. 감사보고서까지 넓힌다 | 넓힌 이유와 다시 찾은 절 |
| `S6 값 조회` | 숫자를 묻는 질의면 재무제표 표에서 값을 직접 꺼낸다 | 찾은 값과 단위 |
| `S6-B 공시 조회` | 계약·투자·증자·지분을 물었을 때만 돈다. 수시·거래소·지분 공시를 표에서 꺼낸다 | 찾은 공시의 이름과 접수일 |
| `S9 근거 조립` | 쓸 절을 골라 근거 글을 만든다 | 절마다 순위·경로·출처·글자 수 |
| `S10 답변 생성` | HyperCLOVA X 로 답을 만든다 | 걸린 시간, 상태, 글자 수 |
| `S10-B 재생성` | 근거에 없는 수치나 기업이 잡혔을 때만 돈다. 한 번만 다시 시킨다 | 무엇이 걸렸는지와 남은 경고 |
| `S11 출력 검증` | 답변에 근거 없는 숫자·공시·기업이 섞였는지 본다 | 경고 내역, 출처 보완 여부, 지시 유출 여부 |

`-B` 가 붙은 넷은 평소에 돌지 않는다. 조건이 맞을 때만 발동하므로 평소
응답 시간에 영향이 없다.

번호는 단계를 가리키는 이름이지 실행 순서가 아니다. 실제로는 `S1 → S3 → S2
→ S7 → S6 → S9 → S10 → S11` 순으로 돈다. `S2` 와 `S3`, `S6` 와 `S7` 이 번호
순서와 다른데, 서로 결과에 영향을 주지 않는 단계라 어느 쪽을 먼저 해도 답이
같다. 번호는 설계 문서와 맞춰 두려고 그대로 뒀다.

## 응답 시간

2026-09-06 실측이다. 노트북에서 서버로 외부 호출한 값이다.

| 질의 성격 | 예시 | 걸린 시간 |
|---|---|---|
| 정형 숫자 | 삼성전자의 2025년 주당 현금배당금은 얼마인가 | 2.3초 |
| 공시 조회 | 삼성전자가 2025년 7월 28일 공시한 공급계약의 계약금액은 | 3.5초 |
| 정성 서술 | SK하이닉스의 배당 정책을 알려줘 | 9.5초 |
| 살아 있는지 | `/health` | 0.12초 |

자체 평가지 28문항을 잇달아 던졌을 때 평균 8.4초, 최대 31.0초였다.

대부분이 HyperCLOVA X 가 답을 만드는 시간이다. 검색은 0.2초 안에 끝난다.

숫자 질의가 빠른 이유가 있다. 본문을 뒤져 숫자를 읽는 대신 재무제표 표에서
값을 직접 꺼내므로 답이 짧고 생성이 빨리 끝난다.

시간 제한은 넉넉히 잡기를 권한다. `timeout=120` 정도면 충분하다.

## 근거를 세 층으로 쌓는다

질의 성격에 따라 세 곳에서 근거를 모은다. 답변의 `근거:` 줄에 어느 층에서
왔는지가 그대로 적힌다.

| 표시 | 어디서 왔나 | 언제 나오나 |
|---|---|---|
| `[값 N]` | 재무제표 정형 표 | 매출액·영업이익 같은 표준 재무 항목을 물었을 때 |
| `[공시 N]` | 수시·거래소·지분 공시 정형 표 | 공급계약·시설투자·증자·사채·자기주식·대량보유를 물었을 때 |
| `[근거 N]` | 사업보고서 본문 | 언제나 |

표에서 꺼낸 것을 앞에 둔다. 뒤에 묻히면 생성 모델이 본문의 다른 숫자를 집는다.

금액은 숫자와 조·억 표기를 함께 싣는다. `22,764,764,160,000원 (22조 7,647억원)`
꼴이다. 단위 환산을 생성 모델에게 맡기지 않으려는 것이다.

### 수시·지분 공시는 본문이 아니라 표로 답한다

거래소공시 1,469건, 지분공시 1,083건, 주요사항보고서 598건은 본문 조각으로
쪼개져 있지 않다. 대신 구조화한 표로 조회한다. 계약금액·투자금액·지분율은
표에 숫자 그대로 있어 본문에서 찾는 것보다 정확하다.

| 표 | 행 수 | 담긴 것 |
|---|---|---|
| `event_contract` | 1,169 | 공급계약 체결·해지, 신규시설투자 |
| `event_major` | 598 | 유상증자·감자·사채·자기주식·합병 |
| `event_holding` | 1,083 | 대량보유상황 |

## 기업을 여럿 다루는 질의

질의가 기업을 둘 이상 말하면 기업마다 따로 검색해 근거를 합친다. 근거가 쓸
글자를 기업 수로 나누므로 한쪽만 실리는 일이 없다.

기업 이름이 하나도 없으면 그룹·업종·시장으로 대상을 정한다.

| 질의 | 어떻게 정하나 | 결과 |
|---|---|---|
| 코스닥 기업들 중에서 … | 시장 | 9곳 중 시가총액 상위 6곳 |
| 전력기기 산업의 … | 업종 | 3곳 |
| 필수소비재 산업에 있는 기업 중 … | 업종 | 4곳 |
| 삼성 그룹의 … | 이름 앞머리 | 8곳 중 상위 6곳 |

한 질의에서 훑는 기업은 6곳까지다. 코스피 61곳처럼 많이 걸리는 질의는
시가총액 순으로 자른다. 몇 곳 중 몇 곳을 골랐는지 `think_trace` 의
`S1-B` 에 남기고 답변 첫머리에도 밝힌다. 전수 조사가 아님을 숨기지 않는다.

기업 이름은 대소문자를 가리지 않는다. `lg생활건강` 과 `LG생활건강` 이 같다.
코퍼스가 한글로 적은 이름을 알파벳으로 써도 찾는다. `LS일렉트릭` · `KT` ·
`SM` · `YG` · `HYBE` · `KAI` 등이다.

## 답변 규칙

과제의 데이터 활용 규칙을 그대로 따른다.

- 답변은 제공된 공시 데이터만을 근거로 만든다.
- 모든 답변 끝에 근거 공시를 밝힌다. 회사·보고서·절·접수일을 적는다.
- 공시에서 확인할 수 없으면 확인되지 않는다고 적는다. 추측하지 않는다.
- 주가 전망·투자 추천·매수 매도 의견은 만들지 않는다.
- 답변에 나온 기업이 근거 원문에도 없고 검색 대상도 아니면 경고를 내고 한 번
  다시 생성한다. 그래도 남으면 답변 끝에 "그 기업에 대한 내용은 공시로 확인된
  것이 아니다" 를 붙인다. 제공 코퍼스 밖 데이터를 쓰지 않기 위해서다.
- 근거에 없는 수치도 같은 방식으로 다룬다.

마지막 항목에 해당하는 질의를 받으면 답을 거절하고 그 이유를 밝힌다. 이는
오류가 아니라 설계된 동작이다.

## 확인해 보는 법

### 브라우저

```
http://211.188.57.111:8000/docs
```

`GET /answer` 를 누르고 `Try it out` 을 누른 뒤 질의를 넣고 `Execute` 를 누른다.

### PowerShell

```powershell
[System.Net.WebRequest]::DefaultWebProxy = $null

$q = [uri]::EscapeDataString("삼성전자의 주주환원 정책이 어떻게 되는지 알려줘")
$r = Invoke-RestMethod "http://211.188.57.111:8000/answer?question_id=Q-001&question=$q"
$r.answer
```

첫 줄이 없으면 그 세션의 첫 요청에 30초쯤 더 걸린다. PowerShell 이 프록시를
찾느라 기다리는 시간이고 서버와 무관하다.

### curl

```
curl.exe -G "http://211.188.57.111:8000/answer" ^
  --data-urlencode "question=삼성전자의 주주환원 정책이 어떻게 되는지 알려줘" ^
  --data-urlencode "question_id=Q-001"
```

## 서버를 직접 띄울 때

소스에서 서버를 새로 띄우려면 `README.md` 의 실행 절차를 따른다. 필요한 것은
`.env` 의 열쇠와 `data/corpus.db` 다. 열쇠 서식은 `env.example` 에 있다.

```
python -m uvicorn src.server:app --host 0.0.0.0 --port 8000
```

기동할 때 형태소 분석기와 기업 마스터를 미리 올린다. 그래서 뜨는 데 10초
남짓 걸리고, 대신 첫 질의부터 정상 속도가 나온다.
