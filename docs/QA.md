# ONBOARDING.md 문서를 읽으면서 생긴 의문점을 정리하고, AI에게 답변을 받는 문서다. 질문에 대한 대답은 본문 인라인 주석으로 하단에 직접 문서를 수정하여 기재한다.

1. 측정 코드를 여럿 두지 마라는 말에서 '새 평가 스크립트를 만들지 말고 --mode 나 --cases 를 늘려라' 라고 하는데, 여기서 말하는 --mode와 --cases가 뭐야? 

> 답. `scripts/eval_body.py` 를 돌릴 때 붙이는 실행 옵션이다. 무엇을 비교할지 고른다.
>
> ```
> --mode=weights   RRF 가중치를 바꿔 가며 잰다
> --mode=stop      STOP 갈래를 켜고 끄며 잰다
> --mode=path      경로 필터를 켜고 끄며 잰다
> --mode=show      검색 결과를 그대로 낸다. 눈으로 본다
> --cases=파일명    다른 질의 세트로 잰다. 기본은 body_cases.csv 37건
> ```
>
> 새로 비교하고 싶은 것이 생기면 `--mode` 를 하나 늘린다. 스크립트를 새로 만들지 않는다. 예전에 셋을 만들었다가 같은 질의에 서로 다른 숫자가 나와 사흘을 잃을 뻔했다.

2. 용어 확장을 어떤 식으로 구현할 것인가? 너무 방대하고 막연해보이는데?

> 답. 아직 안 정했다. 방대해 보이는 것이 맞다.
>
> 지금 판단으로는 뒤로 미루는 편이 낫다. 매칭표가 `IV` 계열은 대체하기 때문이다. "실적 변화" 질의를 층 4로 넓히면 손익계산서 쪽으로 끌려가 오히려 정답에서 멀어진다.
>
> 다만 4번에 적은 대로 `II/1` 의 "어떤 사업을 하는 회사인가" 유형은 매칭표로도 안 잡힌다. 층 4가 정말 필요한 자리는 거기다.
>
> 그래서 전면 사전을 만들지 않는다. 매칭표를 먼저 넣고, 그래도 남는 실패에만 좁게 붙인다. 그러면 대상이 몇 개로 줄어 막연하지 않게 된다.

3. 절마다 '그 절에서만 유난히 자주 나오는 낱말'을 별도 문서로 정리해두고, 질의에서 겹치는 경우 조각을 선순위로 당겨 올리기.

> 답. 맞다. 그것이 `data/eval/pathmap.csv` 이고 이미 44행 있다.
>
> "당겨 올리기" 도 정확하다. 후보에서 빼지 않고 순위만 올린다(`PATH_BOOST = 20`). 잘못 짚어도 정답이 후보에 남아 회복이 된다.
>
> 지금 부족한 것이 둘이다.
>
> ```
> 비어 있다   자동으로 뽑아서 특징 없는 절(II/1 · IV)은 낱말이 안 잡혔다
> 섞여 있다   표 머리글에서 온 일반어가 오탐을 낸다
> ```
>
> 앞의 것은 매칭표가 채우고, 뒤의 것은 `pathmap_review.csv` 가 뺀다.

4. 어떻게 사업의 개요와 이사의 경영진단 및 분석 의견 쪽으로 LLM을 유도할 것인가? 그 두 개의 section으로 직접 유도한 키워드는 무엇인가? 키워드가 안 겹치거나, 너무 범용적이라면. 특히 사업의 개요가 어렵다. 무슨 사업을 하는지 서술하는 절이라, 어느 산업이냐에 따라 낱말이 모두 다르다.

> 답. 절 본문에서 뽑으려니 안 되는 것이다. 산업마다 다른 것은 본문이고, 그 절을 묻는 질의의 표현은 산업이 달라도 비슷하다. 거기서 뽑으면 된다.
>
> 다만 아무 말이나 넣으면 안 되고 전체 빈도를 봐야 한다. 실측이다(전체 절 108,337개 기준).
>
> ```
> 개요    5.4%    쓸 만하다
> 실적    9.7%    쓸 만하다
> 부문   12.9%    경계
> 사업   39.8%    변별력 없다
> 회사   45.3%    변별력 없다
> ```
>
> 그래서 둘의 난이도가 다르다.
>
> ```
> IV     잡힌다.   "실적" "경영진단" "분석의견" "변동 요인" 이 다 드문 말이다
>
> II/1   반쪽만 잡힌다
>          "사업 개요" "사업부문 구성" → '개요'(5.4%) 로 잡을 수 있다
>          "어떤 사업을 하는 회사인지" → 남는 낱말이 ['사업','회사'] 둘뿐이다
>                                        둘 다 40% 넘게 나와 매칭표로도 안 된다
> ```
>
> 즉 `II/1` 의 후자 유형은 매칭표의 한계 밖이다. 층 4로 질의 쪽을 넓히거나 `PATH_MIN`(지금 15.0)을 낮춰야 한다. 표를 넣고 재본 뒤에 정하는 것이 맞다.

5. 사람만이 아는 관계성을, AI도 참고할 수 있는 매칭표로 만들어야 한다. '어느 사업', '실적 변화' 등. 실제로 '어떤 사업을 하는지' 물어보면, 그 의미를 이해하지 못하고 '사업' 이라는 키워드만 뽑아내는 게 문제라는 것인가?

> 답. 그렇다. 실측으로 그대로 나온다.
>
> ```
> "SK하이닉스가 어떤 사업을 하는 회사인지 사업보고서 기준으로 알려줘"
>     → 검색어 ['사업', '회사']
> ```
>
> 다만 문제가 둘로 갈린다는 점이 중요하다.
>
> ```
> 하나   층 1이 "어떤 사업을 하는" 이라는 의도를 못 잡고 낱말만 남긴다
> 둘     남은 '사업'(39.8%) '회사'(45.3%)가 절의 40% 이상에 나와 아무것도 못 가린다
> ```
>
> 매칭표는 둘째를 푼다. 첫째는 못 푼다. 첫째를 풀려면 질의 해석이 "무엇을 묻는 질문인가" 를 알아야 하는데, 지금 층 1은 규칙 기반이라 의도까지는 안 잡는다.

6. "이 낱말이 질의에 나왔을 때, 다른 절을 봐야 할 경우가 있는가?" -> 이 질문을 기준으로 임계치를 결정하라? 차라리 대부분의 절에서 빈번하게 등장하는 단어를 제외하는 '블랙리스트' 개념은 어떤가? 지금처럼 화이트리스트가 아니라. 그 쪽이 훨씬 효과적인 작업이 아닐까?

> 답. 블랙리스트는 이미 두 곳에서 돌고 있다.
>
> ```
> src/query.py   STOP        질의에서 뺄 낱말. 알리 · 기준 · 얼마 · 보고서 …
> src/terms.py   SHARE_MAX   조각 토큰에서 뺄 기준 (0.40)
> ```
>
> 그리고 pathmap 의 점수 계산 자체가 블랙리스트 역할을 한다. 점수가 `(그 절에 나오는 비율) ÷ (전체 절에 나오는 비율)` 이라, 모든 절에 흔한 낱말은 분모가 커져 자동으로 점수가 떨어진다. `사업`(39.8%)과 `회사`(45.3%)가 어떤 절에서도 대표 낱말로 안 잡힌 이유가 이것이다.
>
> 그런데 지금 문제가 되는 `이유` 는 전체 절의 3.3% 에만 나온다. 흔한 말이 아니다. 통계적으로는 변별력이 있고, 어긋난 것은 뜻이다. 표의 "변경이유" 칸에서 온 것이라 질의의 "이유" 와 다른 말이다.
>
> ```
> 블랙리스트가 잡는 것    흔해서 변별력이 없는 낱말      →  이미 잡고 있다
> 블랙리스트가 못 잡는 것  드물지만 뜻이 다른 낱말        →  사람이 봐야 한다
> ```
>
> `pathmap_review.csv` 가 겨냥하는 것이 뒤쪽이다. 화이트리스트를 늘리는 작업이 아니라, 이미 들어간 264개 중 뜻이 어긋난 것을 빼는 작업이다. 그래서 빈도로는 자동화가 안 되고 용례를 붙여 둔 것이다.

7. 즉, 각 절에서(각 목차에서) 등장하는 키워드를 최대한 많이 추려놓는 '화이트리스트'를 매칭표로 만들자는 거잖아?

> 답. 절반 맞다. 두 곳을 정정한다.
>
> ```
> "최대한 많이" 가 아니다
>    점수를 합산하므로, 흔한 낱말 여럿이 우연히 겹치면 문턱을 넘는다
>    절당 6~12개를 권한다. 지금 자동 표도 절당 최대 12개다
>
> "각 절에서 등장하는" 이 아니다
>    "그 절을 묻는 질의에 나올" 낱말이다
>    본문에서 뽑는 것은 이미 자동으로 했고, 그래서 II/1 과 IV 가 비었다 (4번 참조)
> ```
>
> 그리고 화이트리스트만으로는 부족하다. 지금 두 작업이 방향이 반대다.
>
> ```
> pathmap_review.csv   뺀다.   뜻이 어긋난 낱말을 걷어낸다.   혼자 할 수 있다
> 매칭표               채운다.  빈 절에 낱말을 넣는다.        파트너와 함께
> ```
>
> 둘 다 필요하다. 빼는 쪽을 먼저 두는 이유는 지금 있는 표만 고치면 되기 때문이다.
