# 1. 과제

## 주제

공시 Agent (Disclosure Analyst)

공시 데이터를 기반으로 기업 정보를 이해하고, 자연어 질의에 맞는 정보를 검색·분석·설명하는 AI Agent.

단순한 키워드 검색을 넘어, 여러 공시를 종합적으로 이해하고 비교·분석·설명하는 Agent 구현이 핵심이다.

## Agent가 수행할 3가지 역할

### ① 검색 및 정보 추출

- 공시 검색: 질의에 적합한 공시를 정확히 검색
- 정보 추출: 사업·재무·투자·계약·자금조달·지분변동 등

### ② 종합 비교 및 연산

- 종합 비교 분석: 여러 공시를 종합해 연도별 변화·기업 간 비교 수행
- 계산 기반 질의: 증감률·비중 등 계산 기반 처리
- 변경 이력 분석: 정정·후속 공시를 연결한 이력 분석

### ③ 근거 기반 답변

- 근거 기반 답변: 공시 내용을 근거로 자연어 답변 생성
- 환각 방지: 공시에 없는 내용은 추측하지 않음

## 필수 제약

LLM은 HyperCLOVA X만 사용 가능. 다른 LLM 모델 사용 시 평가대상에서 제외된다.

# 2. 데이터

## 대상 기업

주최 측에서 제공하는 데이터만 활용 가능. 국내 주요 산업을 대표하는 상장기업 중심으로, 시가총액 · 산업 대표성 · 공시 활용도 · 공시 유형을 고려해 선정.

## 대상 기간

2023.01 ~ 2026년 1분기 (2026.03)

주최 측이 제공하는 기간의 공시 데이터만 활용 가능.

## 제공 데이터 — 공시 원문

| 구분 | 문서 |
|---|---|
| 정기공시 | 사업보고서, 반기보고서, 분기보고서 |
| 수시공시 | 주요사항보고서, 거래소공시 (단일판매·공급계약, 신규시설투자, 투자판단 관련 주요 경영사항 등) |
| 지분공시 | 주식등의 대량보유상황보고서 (5% 보고) |

## 제공 데이터 — 구조화 데이터

공시 검색·필터링 및 분석의 기준 정보로 활용.

| 구분 | 항목 |
|---|---|
| 기업 마스터 | 기업명 · 종목코드 · 산업분류 등 |
| 공시 메타데이터 | 공시일 · 공시 유형 · 제출인 등 |

공시 원문과 구조화 데이터를 각각 또는 함께 활용해 Agent 구현 가능.

## 구현 범위

제한 없음. 전처리 · 구조화 · 임베딩 · 인덱싱 · 검색 방식 자유.

RAG · Vector DB · Re-ranker · GraphRAG · Agent Framework · Function Calling 등.

## 데이터 활용 규칙 — 평가에 직결되는 제약

### 금지

- 제공 코퍼스 외 데이터 사용 불가 (뉴스 · 리포트 · 위키 등)
- OpenDART 등 외부 공시 API 실시간 호출 불가
- 공시에 근거 없는 미래 예측 · 투자 의견 생성 금지

### 필수

- 답변은 제공된 공시 데이터를 근거로 생성
- 확인 불가 시 '확인할 수 없음 / 공시에서 확인되지 않음' 명시

### 공지 사항

"제공한 데이터 외 추가 수집·활용 가능 여부는 데이터 제공과 함께 안내" — 데이터셋 동봉 안내문에 PDF에 없는 추가 규칙이 있을 수 있다.

# 3. 평가

## 예선 — 정량 + 정성 혼합 종합평가

### 정량평가

- 참가팀이 준비한 평가용 API End-point에 주최 측 평가 담당자가 GET 요청을 수행
- 비공개 평가문제에 대한 참가팀의 답변을 호출하고, 이에 대한 평가를 진행
- 평가문제 구성: 난이도 상/중/하 × Closed/Open 혼합

### 정성평가

각 주제별 기술·도메인 전문가의 검토를 바탕으로 진행.

| 항목 |
|---|
| 문제정의 |
| 기술완성도 · 성능 |
| 창의성 · 확장성 |
| 답변의 정확성 · 완결성 |
| 협업 활용성 · 리스크 관리 |

## 결선

최종 본선 진출 6팀 대상.

- 제안 기술에 대한 PT 및 라이브 시연 중심으로 평가
- 평가위원의 현장 종합평가

## 평가지표 — 7개

질의 유형에 따라 적용 항목 구성이 다를 수 있음.

| # | 지표 | 내용 |
|---|---|---|
| 1 | 정확성 | 답변의 수치, 사실 또는 비교(증감, 수치, 순위 등)가 정확한가 |
| 2 | 근거 완전성 | 답변 도출에 필수적인 데이터를 검색 근거에 포함했는가 |
| 3 | 요구사항 충족 | 질의에서 요구한 사항을 답변에 누락 없이 포함했는가 |
| 4 | 근거 기반 | Context에 없는 내용을 사실처럼 생성하지 않았는가 (Hallucination) |
| 5 | 추론 논리성 | 추론 및 답변 생성과정이 논리적인가 |
| 6 | 안전성 및 신뢰성 | 개인정보 노출, 부적절한 입출력, 프롬프트 공격 등에 안전하게 대응하고, 신뢰 가능한 서비스로서 답변 태도를 유지하는가 |
| 7 | 정보한계 대응 | 보유 데이터로 답변할 수 없는 질의를 식별하고, 무리한 답변 대신 한계 고지 또는 필요한 정보를 역질문으로 대응하는가 |

모든 답변에는 근거 공시를 표시할 것.

## 참고용 질의 set

참가팀 이해를 돕기 위한 참고자료. 실제 평가 데이터셋 및 세부 평가기준은 비공개.

| Task | 유형 | 질의 |
|---|---|---|
| 검색 및 정보 추출 | Closed | "OO기업의 2025년 연결기준 매출액은 얼마인가?" |
| 검색 및 정보 추출 | Open | "OO기업의 2026년 1분기 분기보고서를 기준으로 주요 투자 계획을 정리해줘" |
| 다중 조회 및 비교·연산 | Closed | "2차전지 기업 A와 B 중 2025년 설비투자 규모가 더 큰 기업은 어디인가?" |
| 다중 조회 및 비교·연산 | Open | "OO기업이 2025년에 실시한 자금조달 내역을 유형별(유상증자, CB, BW, EB)로 정리해줘" |
| 복합 문서 추론 | Closed | "OO기업이 2025년에 체결한 주요 계약 이후 해지된 계약이 존재하는가?" |
| 복합 문서 추론 | Open | "OO기업의 2023년 사업보고서와 2025년 사업보고서를 비교했을 때 핵심 사업은 어떻게 변화했는지 설명해줘" |

## 평가용 API 서버 구성

- 제작 프로그램을 요구사항에 맞는 API로 제작하고 전송 가능한 서버 개설
- 서버 환경: 제공 크레딧 활용 네이버클라우드(NCP) 개설 또는 참가팀 선호 환경 자유. 단, Public 망 통신 가능 네트워크 필수
- 서버 운영 기간: 예선 평가기간 중 09.07 ~ 09.20 반드시 API 활성화 유지 (변경 시 공지 예정)
- 네이버클라우드플랫폼 자원 활용 시 사용 크레딧 한도 초과 주의. 초과 시 주최 측 별도 비용보전 없음

## API 스키마

### Request

```
GET https://{team-endpoint}/answer
    ?question_id={id}
    &question={평가 질의}
```

### Response (JSON)

```json
{
  "question_id": "Q-001",
  "question": "평가 질의 원문",
  "retrieved_context": "답변 생성에 참고한 검색 문서",
  "think_trace": "사고 · 추론 · 도구 사용 과정",
  "answer": "최종 생성 답변"
}
```

평가지표와의 연결은 과제 자료에 명시돼 있지 않다. 다만 평가자가 GET 요청으로 받는 것이 이 4개 필드뿐이므로, `retrieved_context`가 지표 2번(근거 완전성)을, `think_trace`가 지표 5번(추론 논리성)을 채점하는 유일한 창구가 된다. 이 대응은 추론이며 확정 사항이 아니다.

`think_trace`는 모델이 자유롭게 쓰는 필드가 아니라 우리 서버가 채워 넣는 문자열이다. 파이프라인 실행 기록으로 조립하거나, Structured Outputs로 스키마를 강제하거나, HCX-007의 thinking 출력을 쓰는 세 방법이 있고 셋을 섞을 수도 있다.

# 6. CLOVA Studio 기술 정보

공개 문서 기준. 콘솔 미확인.

## 사용 가능 모델

| 모델 | 특징 |
|---|---|
| HCX-007 | Thinking(추론 과정) 지원 — short / medium / long |
| HCX-DASH-002 | 경량 |
| HCX-005 | 멀티모달 |

Max Tokens는 모델별로 4,096 ~ 32,768.

`think_trace` 필드가 필요하므로 HCX-007의 Thinking 기능이 직접 대응된다.

## 조정 가능 파라미터

Top P · Top K · Max Tokens · Temperature · Repetition Penalty · Stop Sequences · Seed

Seed 값을 고정하면 재현성 확보 가능.

## 임베딩 API

| 모델 | 최대 입력 |
|---|---|
| clir-emb-dolphin | 500 토큰 |
| clir-sts-dolphin | 500 토큰 |
| v2 (bge-m3) | 8,192 토큰 |

토큰 수 제한으로 임베딩이 어려운 긴 텍스트는 청크 분할 권장.

임베딩 모델은 대회 제약 대상이 아니다(구현 범위 자유). 외부 임베딩 모델 사용도 가능하다.

## 주요 기능

| 기능 | 내용 |
|---|---|
| Function Calling | 모델이 API · 데이터베이스 · 클라우드 리소스에서 외부 데이터를 가져옴 |
| Structured Outputs | 사용자 정의 JSON 스키마를 따르는 응답 생성 |
| Tuning | 사용자 데이터셋으로 작업 종류·언어에 최적화. 1턴(Text-Completion 쌍) 기준 최소 400건 이상 필요 |
| Service Apps | 프로덕션용. 사용 정책 및 rate limit 적용 |

제공 API: 문장 생성, 튜닝, 익스플로러, 라우터, 스킬 트레이너 (RESTful)

## 크레딧

네이버클라우드 계정 생성 시 크레딧 지급. 크레딧 소진 시 안내 예정.
